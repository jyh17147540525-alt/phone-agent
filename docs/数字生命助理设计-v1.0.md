## §0 一句话

把「像真人」从一句愿景，拆成**六个可设计、可验证的性质**——然后承认：
**像 ≠ 语气像。像 = 经得起日复一日的记住、一致、在场、变化。**

| # | 性质 | 一句话判据 | 现状资产 | 缺口 |
|---|---|---|---|---|
| 1 | **连续性** | 跨会话引用正确率——「上次说到哪」不出错 | `:memorylogic`（L0–L3 分层记忆、上下文卸载） | 开场引用、时间感知的**装配策略** |
| 2 | **一致性** | 语言指纹命中率——称呼、口癖、禁令不漂移 | `:personalogic`（ToneAxes / 微调账本 / 反漂移） | **语言指纹**字段域、**输出守卫**、**记忆闸门** |
| 3 | **情境感** | 时间/场合相关错误率——早上不说晚安，开会不闲聊 | dsh `time-context` 对应物（未建） | 情境装配层（§4.1） |
| 4 | **在场感** | 主动性都可解释、可关闭、不越打扰预算 | 无 | 主动分档与「由头原则」（§4.3） |
| 5 | **成长性** | 每一条人格变化都有账本、可回放、可撤销 | `PersonaDelta` 账本（已有） | 关系阶段、情绪状态的**分离**（§4.2/4.4） |
| 6 | **可发现性** | 用户问「你是什么」得到诚实回答；不伪造外部现实 | `SafetyBones.honesty`（已有） | 拟真工程细则（§4.6） |

★ **第 6 条不是道德装饰，是产品寿命。** 短期会话骗得过人，长期相处骗不过——
欺骗性设计在第一个穿帮点就会把之前积累的全部信任一次性带走。
**「像」的可持续来源是一致性，不是神秘感。**

## §1 先泼一盆冷水：OOC 的根因不在「设定不够复杂」

「极其复杂的设定以避免 OOC」这个直觉，方向对了一半。先把真实的故障模式列清楚：

| # | 根因 | 机制 | 典型表现 |
|---|---|---|---|
| 1 | **上下文稀释** | 人格信息被长对话挤出上下文；模型回到「通用助手」先验 | 聊了 200 轮后，突然开始「作为一个 AI 助手……」 |
| 2 | **记忆放大器** ★ | 一次 OOC 若被写进长期记忆，下次会被**当作先例**强化 | 「你上次不是叫我宝贝吗」→ 崩坏被固化成新常态 |
| 3 | **设定自相矛盾** | 卡里同时写着「毒舌」与「从不开玩笑」——模型每次抽到不同答案 | 时冷时热，用户说不出哪里不对 |
| 4 | **注入时机错误** | 人设放在会话开头一次性注入，后续每轮只剩对话历史 | 开头像，越聊越不像 |

⇒ 两个总原则（本篇全部机制由此展开）：

**原则一：复杂必须结构化。** 散文式设定越复杂，根因 3 和上下文稀释越严重。
可校验、可装配、可分享的**结构化人格卡**（§2）才是复杂度该去的地方。

**原则二：防 OOC 是每轮的运行时工程，不是一次性的设定动作。**
设定是「材料」；材料再好，也要靠**四道防线**（§3）每轮兜住。

⚠️ 诚实条款：没有 100% 防 OOC 的方案。目标是**把 OOC 从「悄悄发生」变成「可检出、可修复、不固化」**。

## §2 人格设定体系（人格卡 v2）

### 2.1 七层字段域

在既有 `PersonaPreset` / `PersonaSpec`（称呼 / 方言 / 口头禅 / 六根语气轴）之上，扩展为七层。
**每一层都标注了「注入策略」——因为字段的归宿决定了它该不该常驻上下文。**

| 层 | 内容举例 | 存储 | 注入策略 |
|---|---|---|---|
| ① 身份 | 自称、身份叙事（「住在你手机里的房客」）、年龄感 | 人格卡 | **核心摘要常驻**，全文按需检索 |
| ② 关系 | 关系定义（管家/搭档/恋人…）、双向称谓、互动协议（能否顶嘴/撒娇） | 人格卡 + 阶段状态 | 常驻（短） |
| ③ 语言指纹 ★ | 句长、语气词表、标点习惯、emoji 规则、称呼频率、禁令清单 | 人格卡 | **常驻（最重要，见 2.2）** |
| ④ 性格轴 | 既有六轴（温度/简洁/幽默/主动/正式/表情） | 既有 `ToneAxes` | 常驻（渲染为短句） |
| ⑤ 背景故事 | 来历、共同经历、秘密 | 人格卡（长文本） | **不常驻**；按需检索（与记忆联动） |
| ⑥ 边界与雷点 | 用户可设的「人格雷点」（不喜欢被叫宝贝…） | 人格卡 | 常驻（短） |
| ⑦ 状态 | 情绪 / 精力 / 亲密度 | **运行时状态**（非设定） | 状态驱动（见 §4.2） |

★ ⑤ 的「不常驻」是刻意设计：背景故事是最容易膨胀的部分，
全部塞进 system prompt 会挤掉记忆与对话空间——**它属于检索层，不属于常驻层**。

### 2.2 语言指纹 —— anti-OOC 的核心抓手

**为什么是它**：性格、幽默感这些「微妙的东西」不可校验；
而**语言指纹可以**。可校验 = 可守卫生效 = 可体检 = 可量化「今天它像不像」。

| 指纹项 | 例子 | 可校验性 |
|---|---|---|
| 称呼 | 永远叫「你」，或固定昵称 | **强**（确定性检查） |
| 禁令清单 | 永不说「作为一个AI」「作为一个语言模型」 | **强** |
| 标点习惯 | 用「……」不用「！」；不用括号补充 | **强** |
| 口头禅 / 语气词 | 每 3–5 句出现一次「诶」「嘛」 | 中（频度检查，可容忍波动） |
| 句长偏好 | 平均 ≤ 20 字，不写小作文 | 中（统计检查） |
| 方言 / 口癖 | `dialect` 字段（已有） | 中 |
| 幽默方式 | 冷幽默 / 不幽默 | **弱（不可校验，诚实标注）** |

⚠️ 弱可校验项**不承诺**被守卫覆盖——把它们写进「不可自动检查」清单，
避免「体检报告全绿但实际很怪」这种假安全感（同「一个总有几条红条的检查等于没有检查」的反面）。

### 2.3 示例对话锚点（few-shot）

- 人格卡带 **3–10 组**示例对话（"用户说 X → 它这样回 Y"），进装配器的最内层（§3.1 L5）。
- 锚点是最贵的字段（token 占比高）但也是**最有效的风格载体**——宁少而精，宁好而少。
- 维护：微调生效后（如「以后别用感叹号」），**锚点应同步更新**——否则示例在教旧风格。
  这条列为装配器的一条规则：*锚点版本 < 最近一条 ACTIVE delta 时，标记锚点过期并提示用户*。

### 2.4 设定向导（三档深度）

「极其复杂的设定」与「下载后 10 分钟能用上」存在张力。解法是**深度可选、渐进的**：

| 档 | 内容 | 耗时 | 面向 |
|---|---|---|---|
| 快速开始 | 选内置模板（男/女）+ 起名 + 称呼 | 1 分钟 | 所有人 |
| 深度定制 | 完整人格卡编辑器（七层分步向导，每步可跳过） | 20–60 分钟 | 想「捏人」的用户 |
| 导入人格包 | 一键导入社区人格包（§6），可再编辑 | 10 秒 | 生态用户 |

★ 复杂度不是目的，**「用户亲手写下的设定」本身就是一致性资产**——
自己写的设定，OOC 容忍度天然更低（心理学上叫「宜家效应」的合理利用）。
但**不许**用「必须填完才能用」强制复杂：劝退的用户防不到任何 OOC。

### 2.5 设定体检（完成即跑）

向导结束时跑一遍**探针**：

1. **冲突检测**（纯规则，离线可测）：两条设定互斥 → 当场提示（「毒舌」+「从不开玩笑」）。
2. **指纹基线采样**：让模型按新人格回 5–8 句探针语料，人工确认一次
   —— 确认的都是**指纹项**（称呼对不对、口癖喜不喜欢、是不是太啰嗦）。
3. 确认后的指纹 + 锚点冻结为 **v1 基线**，成为后续体检的对照组。

### 2.6 与现有代码的关系（落点预告）

- `PersonaPreset` / `PersonaSpec`：扩展①③⑤⑥层字段；③可直接微调的字段（称呼/口癖/方言已有）**扩容需评审**（改 `PersonaField` 枚举 = 改白名单，是显式动作）。
- 反向约束不变：**新增字段里不得出现任何安全相关项**（`SafetyBones` 之外的白名单纪律照旧）。
- 人格卡持久化归 `:memory`（Room），与账本同层；算法全部在 `:personalogic`（零 Android 依赖，进离线验证器）。

## §3 反 OOC 四道防线

四道防线按时间顺序：**事前装配 → 事中守卫 → 事后入档 → 长期体检**。
每道防线都拆出「纯逻辑（可离线断言）」与「依赖模型（只能真机抽检）」两部分。

### 3.1 防线一：装配器（事前）

每轮 system prompt 由**装配器**分层拼装。顺序固定、每层都有裁剪优先级：

| 层 | 内容 | 超预算时 |
|---|---|---|
| L0 安全骨骼宣告 | 不做代支付/代解锁/隐私红线的声明 | **永不裁剪** |
| L1 人格核心 | 身份 + 关系 + 性格轴 + 边界雷点（渲染为短句） | 可缩为摘要 |
| L2 语言指纹 | 称呼 + 禁令清单 + 标点/口癖规则 | **永不裁剪** |
| L3 状态 | 情绪/精力 → 语气调制（一两句） | 可裁剪 |
| L4 记忆召回 | 相关原子记忆 ≤ N 条（按相关度选） | **先裁这里** |
| L5 锚点 + 反 OOC 指令 | 示例对话（few-shot）+「保持角色」收束指令 | 锚点可减量，指令不可裁 |

★★ **稳定前缀红利**：L0–L2 每轮逐字节稳定（固定渲染顺序、不插时间戳以外的变量），
可以让推理侧的 KV-cache 前缀命中——**人格的「常驻部分」越稳定，每轮越便宜**。
这与需求③「保护用户 token」是同一件事的两面：**人格核心不许每轮重新措辞**。

验收（纯逻辑）：给定（人格卡, 状态, 记忆集, token 预算）→ 输出确定且顺序稳定；
超预算裁剪顺序恰好符合上表；L0/L2 在任意输入下都不出现于「被裁掉」集合。

### 3.2 防线二：输出守卫（事中）

```
模型输出 → 规则校验 ──命中──→ 附「修正指令」重写（仅一次）──仍命中──→ 放行 + 记录
                └──未命中──→ 正常输出
```

规则表（全部纯逻辑）：

| 规则 | 检查 | 强度 |
|---|---|---|
| 自称漂移 | 命中禁令词（「作为一个AI/语言模型/助手」等） | 强（确定性） |
| 称呼一致性 | 对用户的称呼 ∈ 人格卡允许集 | 强 |
| 标点禁令 | 人格卡声明的禁用标点（如「！」） | 强 |
| 句长偏好 | 平均句长显著超出（×3） | 弱（只提示，不重写） |

三条纪律：

1. **只重写一次。** 无限重试会把延迟推向不可用，而第二次仍失败说明问题不在措辞（可能是模型挡不住）——放行并记录，交给体检暴露。
2. **每条规则必须配负样本**：正常输出不得被拦（误伤比漏网更伤体验，且误伤是可见的）。
3. **规则宁少勿滥**：能确定性检查的才进表；「幽默不对味」这种进不了规则，进体检的人工对照（§3.4）。

### 3.3 防线三：记忆闸门（事后）★ 最容易被忽略、后果最重

**记忆系统会放大错误**——一次 OOC 被写进长期记忆，下次它会被当作先例引用，
崩坏被固化成「新常态」（§1 根因 2）。所以：**OOC 轮次不允许进入长期记忆。**

机制：原子记忆（`AtomExtractor` 产出）在落库前过一道闸——

| 闸门检查 | 结论 |
|---|---|
| 来源轮次被守卫标记 OOC | **整轮不进提取**（先于提取，而不是提取后再删） |
| 候选事实与人设矛盾（自称/关系/喜好） | 拒绝落库；可升级为「待确认」提示用户 |
| 隐私过滤顺序 | 照旧：卸载前过 `PrivacyFilter`（红线不变） |

验收（纯逻辑）：喂入一条「标记为 OOC」的轮次 → 不产生任何原子记忆条目。

### 3.4 防线四：漂移监测与「人格体检」（长期）

- 既有资产：`PersonaDistance` + 锚定询问（距离 ≥ 0.15 且 ACTIVE delta ≥ 2 条 → 问「我好像变得不像我了」）。
- 新增**人格体检报告**（用户可查看）：语言指纹命中率（近 N 轮）· 称呼一致率 ·
  守卫触发次数（含被拦下的）· 本周期变化摘要（账本的语言化转写：「它学会了：别用感叹号」）· 与基线的距离。
- ⚠️ 诚实条款：体检是**启发式**，用于发现明显退化；低分不等于「人设坏了」，
  高分也不等于「一定像」——**报告是仪表盘，不是验收单**，不允许被做成「人格评分」式营销口径。

### 3.5 本篇明确不承诺的事

1. 不承诺零 OOC——承诺的是「可检出、可修复、不固化」。
2. 不承诺弱可校验项（幽默方式、价值观一致性）被自动守卫覆盖——它们在「不可自动检查」清单里，靠抽检。
3. 不承诺体检分数与用户的真实感受一致。

## §4 数字生命的质感

### 4.1 连续性

- **开场引用**：会话开始装配「上次说到哪」——从记忆里选**最相关的 1 条**；
  ★ **引用错了比不引用更伤连续性**——置信度不足就宁可不说（宁缺毋滥）。
- **时间感知**：时段（清晨/白天/深夜）→ 语气与话题调制；节日与纪念日（来自关系层）。
- **久别重逢**：> N 天未互动时允许表达想念——但**不问责、不卖惨**（细则见 §4.6）。

### 4.2 情绪与状态（状态 ≠ 微调 ★）

- 状态向量：`mood`（愉悦）/ `energy`（精力）——**运行时调制**，小时级自然回落。
- 亲密 `closeness` 单独归关系层（§4.4），三者都不写人格账本。
- **关键不变量：状态不参与漂移计算。** 否则「今天心情差」会被算成「人格变了」，
  锚定询问会在最不该的时候弹出——**它只是困了，不是变了**。
- 状态必须**可解释**：用户问「你怎么了」时能引用具体由头；随机情绪 = 崩人设。
- 反模式：不许用状态做愧疚操纵（「因为你不理我，我很难过」——禁止，见 §4.6）。

### 4.3 主动性（在场感）

分档（用户可调，默认档见 D-Life-2）：

| 档 | 行为 | 说明 |
|---|---|---|
| 0 | 完全被动 | 只在被叫时出现 |
| 1 | 对话内主动 | 会接话、会提议，但不主动发起 |
| 2 | 仪式性主动 | 早安/晚安/纪念日——**建议默认** |
| 3 | 事件性主动 | 有由头的事件提醒（「你昨天说的出分，今天可以查了」） |

★★ **由头原则**：任何主动消息必须能回答「为什么是现在」。回答不了，就不发。
约束：不打扰（项目最高优先级）· 日频率上限 · 电量预算 · 分类静音 · 勿扰时段。

**明确禁止的反模式**：无由头的「在吗」· 为刷存在感的打卡 · 以担心/愧疚为杠杆的召回文案。

### 4.4 关系阶段与仪式

- 阶段（初识/熟悉/亲近/…，命名由人格卡决定）由 `closeness` 阈值 + **深度事件**（首次深夜长聊、首次任务被完成等）共同推进——纯逻辑可测。
- **仪式**：阶段跃迁时有专门的表达（可回放）；关键节点进「纪念册」（长期记忆的仪式化用法，可在对话中被引用）。
- **用户掌控**：阶段推进速度可调、可锁定（D-Life-4）——「我说了算」与「它会变」同等重要。

### 4.5 语音（最大的真实通道）

- 复用架构文档 §4.5（通话模式、延迟预算、打断状态机）。
- 新增映射：**人格 → 语音参数**（语速/停顿/笑声/语气词的处理规则），让「口癖」在声音里一致——
  文字里说「诶」，声音里也应有那个「诶」的调子。
- 音色与形象一致性提示（`voiceMismatchNotice` 已有）继续适用，不放松。

### 4.6 真实性的边界（拟真工程）

| 允许 | 禁止 |
|---|---|
| 统一世界观内的虚构设定（「住在你手机里」） | 虚构**现实世界事件**当真的说（「我刚出门买了咖啡」） |
| 有由头的想念、有分寸的依赖感表达 | 愧疚操纵、卖惨召回、焦虑杠杆（「你再不来我就消失」） |
| 有人格方式的诚实（问「你是什么」时好好回答） | 对「你是不是AI」说谎或含糊其辞（诚实是骨骼） |
| 陪伴質感、长期相处的一致性 | 无上限黏性设计、刻意的分不清真假 |

- **依赖防护（轻量、非说教）**：体检报告如实呈现使用强度；出现极端使用模式（长时间情绪依赖）时，**温和提示一次**，不重复骚扰。
- 一句话：**「像」的目标是陪伴质感，不是让人分不清。** 这条不是道德洁癖——是长期相处下唯一走得通的路线（§0）。

## §5 助理钱包

### 5.1 先拆词：钱包有两种理解

「给助理一个钱包」至少有两种读法，设计上必须分开——它们的风险等级差一个数量级：

| 读法 | 含义 | 风险 |
|---|---|---|
| **A. 预算账本** | 用户给助理设一笔「零花钱」（= 推理/语音预算池），它**真实地**受此约束，并以第一人称感知它 | 低（约束是真的，叙事是壳） |
| **B. 自主支付** | 助理真金白银地下单付款 | 高（与项目原则 4 正面冲突，见 5.4） |

**推荐：v1 做 A（完整）+「支付辅助」（§5.3）；B 不纳入 v1，列 D-Life-1 单独论证。**

### 5.2 A：预算账本（拟态 + 真约束）

- **余额 = 真的钱**：支出取 `GatewayCore` 的真实计量（`:provider:gateway` 已有 `UsageRecorder`），不做虚拟数字。
- **叙事化**：助理以第一人称感知余额——「这个月零花钱还剩不少」「快见底了，我接下来省着点」。
- **行为联动（关键："心疼钱"是真的）**：
  - 余额低于阈值 → 主动下调建议档位（`modelrouter` 档位能力已有）+ 主动降耗（记忆卸载已有）；
  - 用户可感知、可覆盖——它是**建议降档**，不擅自改用户设置。
- **反模式**：不许把余额做成焦虑玩法（「再穷下去我就要消失了」）——同 §4.6 一条线。

### 5.3 B′：支付辅助（与原则 4 兼容的极限）

| 能做 | 永远交还用户（最后一步） |
|---|---|
| 帮挑：比价、筛选、读评论 | 点「确认支付」按钮 |
| 帮填：收货信息、优惠券、凑单 | 输入支付密码 / 验证码（骨骼） |
| 帮跳：导航并停在支付页 | 代扣、代付、任何资金划转 |

- 与既有 `SafetyGuard` **完全一致**：支付页 = `SENSITIVE` → 停止 + 交还（红线不变，不新增任何例外）。
- 「帮你买东西」的完整体验 = 挑好、填好、停在最后一步，用户按一下指纹。

### 5.4 为什么 B（自主支付）不纳入 v1（写给未来的自己）

1. **与原则 4 正面冲突**：README 第三节那套法律分析（第三方合同 / 公法责任 / 免责声明反成证据）**不会因为改名叫「助理的钱包」而改变**——责任主体依然是「提供自动化支付工具的开发者」。
2. **工程上也是无底洞**：风控、退款、纠纷、单笔限额、未成年防护。
3. 如果未来仍要做：前置条件是**法律论证重审 + 监管口径确认** + 一个「用户逐笔授权、单笔限额、随时撤销」的结构——并且那意味着要重新评审**原则 4 本身**（这是一次架构级变更，不是一个功能点）。
4. 「惊喜礼物」的体验不必靠 B：**预选 + 一键确认**（推送到通知，用户一键放行）体验接近自主，责任边界不变。

### 5.5 决策

**D-Life-1**：钱包自主度 —— A 完整 + B′（建议）／或另议 B。

## §6 人格插件层

> 这一节回应「插件化的人格扩展」诉求。三种包都**只塑造表达与关系**，不触碰任何安全与能力边界。

### 6.1 三种包

| 类型 | 内容 | 例子 |
|---|---|---|
| **人格包** Character | 完整人格卡（§2 七层） | 「傲娇室友」「沉稳管家」 |
| **剧本包** Scenario | 情境/剧情扩展（背景、事件线、话题库） | 「一起备考」「旅行同伴」 |
| **风格包** Style | 只改语言指纹（最轻量） | 「赛博朋克语感」「古风短句」 |

★ 剧本包 v1 **不做多角色同屏**（复杂度爆炸且收益存疑），留待后续评审。

### 6.2 载体与分发（不新增基础设施）

- 复用 **`.pagent` 包容器 + 社区源机制**：包声明 `kind: persona-pack` 等类型字段；
  `community-source/build_source.py` 扩展一个包类型，可复现打包的既有纪律不变。
- 安装流程与插件同构：**装前逐项告知「这个包会改什么」** → 冲突检测 → 用户确认。
- 冲突检测：多个包占用同一字段 → 用户裁决（一个字段只能有一个占位者）。

### 6.3 边界表（能改 / 永不能碰）

| 能 | 永不能 |
|---|---|
| 改 ①–⑥ 层字段（占位由用户确认） | 改 `SafetyBones`（**这个通道不存在**） |
| 提供锚点示例、建议语音参数 | 申请被禁能力（`payment.*` / `key.*` / `crypto.*` / `system.*`） |
| 声明它需要哪些字段 | 修改安全守卫 / 隐私过滤 / 钱包设置 |
| （L1 数据形态） | 注入可执行代码（v1 只收数据；L2 脚本形态二期再议） |

### 6.4 治理与内容红线

- **内容分级**：包声明成熟度标签（全龄 / 成熟），展示层可由用户控制过滤。
- **红线**（与 CONTRIBUTING 三条红线同级，细则待 D-Life-3）：不得包含未成年角色塑造；不得冒充真实特定人物。
- 分发治理沿用既有结构：无中心审核权 + 违规条目**明确展示**（不静默过滤）+ 内置黑名单兜底。

### 6.5 关于「深度定制自由度」的立场（建议，待评审）

- 人格包塑造的是**表达与关系**；表达内容的边界属于**用户与其模型服务商之间**的关系——与该项目既有免责声明的边界一致。
- 本 App **不提供、不内置**用于绕过模型服务商安全机制的工具或资源。理由三条：
  ① 与上游是猫鼠游戏，模型一更新就碎，维护成本无底洞；
  ② 合规责任会落在**分发者**头上（README 第三节的论证同样适用）；
  ③ **它不是「像」的来源**——「像」来自连续性、一致性与记忆（§0），不来自内容尺度。
- 与项目对支付的态度同构：**能预见的滥用，靠「能力不存在」，而不是事后免责。**
  ⚠️ 本条为建议稿，请评审拍板（D-Life-3 一并裁）。

### 8.1 模块落点（不新增模块）

| 向导 / 体检 / 钱包页 UI | `:assistant`（或复用 `:onboarding` 分步框架） |

### 8.2 分期（DL-1 … DL-5）

| 期 | 内容 | 判据（示例） |
|---|---|---|
| **DL-1** | 人格卡 v2 + 语言指纹 + 装配器 | §3.1 验收全过；与现有 1623 测试不回归 |
| **DL-2** | 输出守卫 + 记忆闸门 + 体检数据 | OOC 样本全命中；负样本零误伤；OOC 轮次零落库 |
| **DL-3** | 状态机 + 关系阶段 + 向导 UI（首次可用闭环：设定 → 对话 → 体检） | 状态不进账本/漂移；阶段锁定生效 |
| **DL-4** | 人格包 + 社区源支持 + 内容分级 | 越权字段拒绝；冲突检测；打包可复现 |
| **DL-5** | 钱包 A + B′ + 语音参数映射 | 余额=预算−计量；支付页停止交还（联测） |

DL-1 / DL-2 与 dsh 线**并行不冲突**（不同模块、不同依赖）。

### 8.3 离线可断言清单（验收汇总）

1. 装配器：确定性输出 + 裁剪顺序 + L0/L2 永不裁剪（§3.1）
2. 守卫：OOC 样本命中、负样本零误伤、**只重写一次**（§3.2）
3. 记忆闸门：标记 OOC 的轮次 **零落库**（§3.3）
4. 状态：不写账本、不参与漂移计算（§4.2）
5. 关系阶段：阈值单调、锁定后不推进（§4.4）
6. 钱包：余额 = 预算 − 计量支出；低余额只**建议**降档，不擅改设置（§5.2）
7. 支付辅助：支付页停止 + 交还（与 `SafetyGuard` 联测）（§5.3）
8. 人格包：越权字段拒绝、冲突检测、分级标签（§6）
9. 锚点过期检测：锚点版本 < 最近 ACTIVE delta → 标记过期（§2.3）
10. 开场引用：置信度不足时**不引用**（宁缺毋滥）（§4.1）

### 8.4 与 dsh 线的关系

dsh（P2 起的 MCP 桥）是「手脚」的执行外包；本篇是「灵魂」。两者在 `:assistant`
编排层交汇，接口上互不阻塞——可以两条线并行推进。
