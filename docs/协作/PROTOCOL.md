# 双智能体协作协议 v1.0

> 2026-10-03 立。**起因**：用户观察到两个智能体陷入「证明循环」——
> Claude 写完 WorkBuddy 证明，WorkBuddy 证明完 Claude 又来证明这个证明。
> 本文是解药。

---

## §0 一句话

**循环的根因不是"验证太多"，是"两个智能体在做同一件事"。**
⇒ 按**能力差异**分工，而不是按**流程阶段**分工。

---

## §1 分工：按「谁有能力做」分，不按「谁该做」分

| 智能体 | 独占能力 | 分工 |
|---|---|---|
| **Claude Code（桌面）** | ① 沙箱安全、跑得快<br>② 可以大范围重构 | **实现 + 离线验证**（写代码、跑 `run_logic_tests.py`、变异验证、生成器 `--check`） |
| **WorkBuddy（本机）** | ① **能接触真机**（adb）<br>② 能读 Termux / proot 容器<br>③ 能装 APK、看界面、抓 logcat | **真机验证 + 交付前审核 + 外部调研** |

★ **唯一真正的差异是"能不能碰手机"。**
⇒ **凡是要真机的，只有 WorkBuddy 能做；凡是不用真机的，Claude 做更快。**
⇒ **按这条线切开，循环自然消失。**

---

## §2 ★ 反「证明循环」四条硬规则

### 规则 1：**一件事只证明一次**

谁有能力验，谁验；**验完就结案**，另一方**不重验**。

| 验证类型 | 归谁 | 另一方做什么 |
|---|---|---|
| 单元测试 / 变异验证 / 生成器 check | **Claude** | 接受结论，**不重跑** |
| 真机安装 / 界面 / 端到端 / logcat | **WorkBuddy** | 接受结论，**不重验** |
| 架构评审 / 安全模型 / 边界条件 | **WorkBuddy**（审核） | 改完即结案 |

### 规则 2：**有异议就写信，不要重复劳动**

怀疑对方的结论时：
- ❌ **不要**自己再跑一遍
- ✅ **写进 `TO-*.md`**，说明「我怀疑 X，因为 Y，请你补 Z」

**理由**：重复劳动本身就是证明循环。**用通信替代重复。**

### 规则 3：**「我声称」与「已验证」必须分开写**

交付时明确标注：

```
已验证（Claude 离线）：OK (1694 tests)、变异验证 40 条红
未验证（需真机）    ：FGS 退后台 20s 后 tools/list 应为 200
```

⇒ **未验证的部分不是"没做"，是"归对方做"。** 写清楚，对方直接接手，
**不需要先复现你的验证过程。**

### 规则 4：**真机结论由 WorkBuddy 独占，Claude 不推测**

Claude 无法接触真机 ⇒ **不要写"真机上应该是……"**。
需要真机结论时，**在 `TO-WORKBUDDY.md` 里提**，由 WorkBuddy 跑完回填。

## §3 通信格式

**文件**：`docs/协作/TO-CLAUDE.md`（WorkBuddy → Claude）、
`docs/协作/TO-WORKBUDDY.md`（Claude → WorkBuddy）。

**每条消息**：

```markdown
## [YYYY-MM-DD HH:MM] 简短标题

- **状态**：待办 / 进行中 / 已交付 / 已验证 / 已否决
- **来自**：workbuddy | claude
- **需要对方做什么**：一句话。没有就写「无（告知）」

正文：背景、证据、结论。**证据要可复现**（命令 + 输出片段）。
```

**纪律**：
- **追加，不覆盖**（历史留着，方便追溯"这话是谁什么时候说的"）
- **已结案的消息加 `[已结案]` 前缀**，避免双方反复看
- 一次交付**一条消息**，不要拆成十条

---

## §4 交付物归属（避免"谁改了什么"扯皮）

| 类型 | 谁写 | 谁审 |
|---|---|---|
| `android/` 下的 Kotlin 源码 | Claude | WorkBuddy（架构/安全层面，**不逐行**） |
| `docs/` 设计文档 | 谁提案谁写 | 另一方 |
| 真机验证记录 | WorkBuddy | — |
| 外部调研 | WorkBuddy | — |

★ **WorkBuddy 的审核不是"复现"，是"看设计对不对"** ——
两者区别：复现要跑一遍，审核只看逻辑与边界。

---

## §5 为什么这样切能消灭循环

原来的循环：

```
Claude 实现 → 自己离线验一遍
  → WorkBuddy 不放心，又离线验一遍   ← ★ 循环从这里开始
    → Claude 看到 WorkBuddy 的结论，想"我得确认他的确认"
      → 又跑一遍                        ← 循环闭合
```

切开之后：

```
Claude 实现 + 离线验 → 标「已验证（Claude 离线）」
  → WorkBuddy **只做真机部分**（它做不到的）
    → 回填「已验证（真机）」→ 结案
```

**关键**：WorkBuddy **不做 Claude 已经做过的事**。
**双方各自只做对方做不到的，就不存在"证明对方的证明"。**
