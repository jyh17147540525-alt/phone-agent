# 在场模式：基本实现（她自己上网看看、自己来找你）

> 2026-11-15｜用户原话（m05259）：「打破第四面墙的那个模式，你要推进到基本实现的版本」
> 前情：一期「她自己的今天」（`LifeformDay.kt`）、二期「独立记忆库 + 独立页面」已交付。

## 一、「基本实现」差在哪

一期二期做完，在场模式已经是「她有自己的今天、自己的记忆、自己的页面」。但有三处
让它停在了 demo：

1. **她看不见外面**。整个仓库里没有一项联网见闻能力（`web_search|news_search|open_url`
   全零命中）。她能说的「今天」全是本地生成的。
2. **她不会自己开口**。`proactiveTick()` 存在，读的是「当前会话 + 天气 + 久未说话」，
   既不知道她在上网看到什么，也不知道她这一天做了什么 —— 全局管线对所有模式一视同仁。
3. **纪律段本身是假话**：`LifeformDiscipline.kt` 写着

   ```
   外面的世界你能看见的只有他给你的那一点：他说的一句话，他拍的一张照片。
   ```

   加了联网之后这句是**事实错误**。模型只能二选一：按设定说（见闻白抓），
   或者违背设定（说自己在网上看到的东西）。它多半选前者。

## 二、四个决定，以及为什么

### 1. 门槛不复制，只做内容

主动消息的门槛（12 轮、3 小时没说话、5 小时没发过、23–8 静默）已经在
`android/legacy/src/main/kotlin/com/pocketagent/legacy/ProactivePlanner.kt` 里，
有离线测试钉着。`:personalogic` 再做一套的话，两套阈值迟早漂移 —— 而且漂移时
**不会有任何测试变红**。所以 `LifeformPulse` 只回答「这一句说什么由头」，
「该不该发」仍然问 `ProactivePlanner.decide`。

### 2. 主动消息只发通知，不写进会话

`TurnPairing.pair()` 遇到没有提问的 ASSISTANT 轮会产出 `prompt = null`，
`android/app/src/main/kotlin/com/pocketagent/ui/tasks/TasksScreen.kt:2283` 把它渲染成
「（这一轮的提问没有保存下来）」的卡片。

要让它正常出现在会话里，就得给 `TurnEntity` 加一个「主动发起」标记 ——
那是数据库迁移，代价远大于本轮收益。所以：**通知发出去，会话不动**。
用户点开通知进来看她，那一轮才是真的对话。

### 3. 取不到网不算失败

`WebDigest.pick(dayIndex, fetched)` 永不返回 null：拿不到就用 12 条确定性兜底池里
按天取一条。理由是这个模式的体验核心是「她今天看到点东西」，不是「她成功联网了」。
网络抖一下就让她发呆一整天，是设计上的错。

兜底池只放**可为真的常识**（雨前土味的来源是放线菌孢子、旧书的甜味来自木质素分解、
海獭睡觉会牵手防漂走），不放「今天某地发生了什么」—— 那种编出来会被用户当场戳穿，
而常识不会。

### 4. 一天锁一条

`lifeformWebItem()` 把当天选中的那一条锁在 `lifeformWebLocked` + `lifeformWebLockedDay`
里。之后的刷新只更新 `lifeformWebFetched`，**不碰已锁的那条**。
否则她上午说看到企鹅，下午说看到海獭 —— 一天里"翻到的东西"变两次，比不联网更假。

## 三、新文件

### `WebDigest.kt`（纯函数，无 IO）

`android/personalogic/src/main/kotlin/com/pocketagent/personalogic/WebDigest.kt`

- `parseSummary(json)`：维基 `page/random/summary` 的 `title` + `extract`。
- `parseHitokoto(json)`：一言的 `hitokoto` + `from` + `from_who`，标题拼成
  `某某的《某》` / `《某》` / `某个人写的一句话`。
- `build()` 的拒绝条件：标题空或超 40 字、正文短于 24 字、命中
  `消歧义|可以指|可能是指|多义词|是一个目录|本条目`（这些是条目索引不是内容）。
- `trimExtract()`：单行化 → 按句号切 → 贪心拼到 150 字。**不按字数硬切** ——
  会切在「土壤里放线菌的孢」这种地方，念出来是故障。截断时先削掉句尾标点再加省略号，
  否则是「…孢子。…」，读起来像结巴。
- `promptSection(item)`：

  ```
  ## 你在网上看到的

  今天你在网上看到「标题」：正文

  这是你自己翻到的，他不在场。他没问就不必说，聊到了再提，用你自己的话讲，别念原文。
  ```

  三句各治一个真实失败模式：不说清来源 → 她会当成"他告诉我的"；不写"他不在场" →
  她会说"我们今天看到的"；不写"别念原文" → 她开口就是维基百科腔。

### `LifeformPulse.kt`（纯函数）

`android/personalogic/src/main/kotlin/com/pocketagent/personalogic/LifeformPulse.kt`

- 由头四种：`WEB`（今天在网上翻到的东西）、`NOW`（手上正在做的这件事）、
  `EARLIER`（今天早些时候做过的一件事）、`MISS`（没什么由头，就是想跟他说句话）。
- 选择用 `Math.floorMod(seed * 31 + hourOfDay.toInt(), order.size)` ——
  **要把"几点"掺进 key**。只用日期当种子的话，她一天到晚拿同一个由头开话，
  比不发还假。
- `picked == lastReason` 且候选多于一个时取下一个，避免连着两次同一个由头。
- `MISS` 只在空闲 ≥ 6 小时时进候选：这是唯一一条"纯粹因为想你"的消息，
  它不该在刚聊完的时候就出现。
- `MAX_PER_DAY = 2`。一天两条以上，"她自己来找你"就变成了推送。

### `WebReader.kt`（`:app/assistant`，只做 IO）

`android/app/src/main/kotlin/com/pocketagent/assistant/WebReader.kt`

照 `SituationReader.kt` 的路子：`HttpURLConnection`、5 秒超时、显式 UA
（维基不带 UA 会 403）、`Accept: application/json`、响应体截到 20 KB、
任何异常返回 null 不抛。两个源按顺序试：维基随机条目 → 一言（文学/诗词/哲学三类）。
都不需要 Key。

## 四、容器接线（`AppContainer.kt`）

| 位置 | 做了什么 |
|---|---|
| `proactiveTick()` 开头 | `if (chatMode().isAlive) { lifeformProactiveTick(); return }` |
| `proactiveLine` 尾部 | 抽成 `oneShot(prompt, maxChars)` 公共方法，两处共用，**没有抄第二份** |
| 新增 `lifeformProactiveTick()` | 读今天的会话/今天/见闻 → `LifeformPulse.plan` → `notifier.tick` → 计数与去重 |
| 新增 `lifeformPulseLine(plan)` | 人设 + 今天 + 见闻 + `plan.promptText` → `oneShot(prompt, 120)` |
| 新增 `lifeformWebItem/Section` | 按天锁定一条；开关关掉返回 null / 空串 |
| 新增 `refreshLifeformWeb()` | 防重入；只写 fetched；成功记 `Timber.i("在网上翻到了：%s")` |
| 提示词装配 | `lifeweb` 与 `lifeday` 合成 `lifeBlock` 插进 `whereWithLife` |
| 装配日志 | 多一项「网上 有(N 字)/无」 |
| 启动预热 | 主动消息循环启动时先抓一次，失败只记 debug（有兜底池） |
| 两个开关 | `lifeform_web_v1`、`lifeform_proactive_v1`，默认开 |

`lifeformProactiveTick()` 的每日计数与「上一次由头」只在内存里（跨天清零）。
理由：这两个值的价值只有"今天别重复"，重启后重复一条不算故障 ——
为它加一个持久化字段，收益不抵序列化兼容的风险。

## 五、纪律段那句为什么必须改

`android/personalogic/src/main/kotlin/com/pocketagent/personalogic/LifeformDiscipline.kt:67`

```diff
- 外面的世界你能看见的只有他给你的那一点：他说的一句话，他拍的一张照片。
+ 网上的东西你能看到，但只能看，去不了：手伸不出这块屏幕，风也吹不到你身上。
```

改这一句的时候有个陷阱：**不能顺手把"去不了"也删掉**。联网只给了她眼睛，
没给她腿。删掉"手伸不出这块屏幕"，她会说「我今天去了海边」——
这比原来那句假话更严重，因为它骗的是"我真的活在你身边"这件事本身。

## 六、设置开关

设置页新增两行（`SettingsScreen.kt`，紧跟在「后台 AI」之后）：

| 行 | 开 | 关 |
|---|---|---|
| 让她上网看看 | 她今天会自己在网上翻到点东西；只取一条，不搜你的事 | 不联网，今天翻到的只是常识兜底，不会提到新闻 |
| 她自己来找你 | 聊得久了、你又半天没说话，她可能发一条消息过来 | 她不会主动发消息（你找她时一切照常） |

★ 容器里这两个字段是普通 `@Volatile var`，界面侧必须在 `AppShell.kt` 用
`remember { mutableStateOf(...) }` 承接 —— 直接读 `container.lifeformWebOn()` 的话，
点开关不会重组（这个坑在本项目踩了四次）。

## 八、明确没做的

1. **没做网页正文抓取**：只用维基摘要与一言。抓正文要处理 HTML、正文提取、
   广告清洗 —— 那是另一个工程，而且失败率会影响"她今天看到点东西"的稳定性。
2. **没做主动消息写进会话**：需要 `TurnEntity` 加标记 = DB 迁移（见二.2）。
3. **没让见闻参与记忆抽取**：见闻是当天的，抽进记忆会变成"她记得自己看过某条维基"，
   那是事实而不是陪伴。
4. **没做「她今天想去哪」**：仍是文字层面的"想出去"。
5. **没装机、没 push**。
