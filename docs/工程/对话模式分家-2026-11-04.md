# 对话模式分家（角色扮演 / 工作）—— 2026-11-04

> 用户原话：“我计划给这个软件的对话功能分家，角色扮演是一个功能，工作模式是一个功能，
> 可以像电脑端豆包那样，切换对话模式和工作模式，但工作模式，是有人格的工作，
> 语气，习惯，等等都要按照人格设定的来。”

这句话的重心在后半句：**工作模式不是把人格关掉，是让她用自己的人格的嘴办事。**
所以这份实现的验收点不是“两个模式都通了”，而是“工作模式下她听起来还是她”。

## 一、模式是什么

`android/personalogic/src/main/kotlin/com/pocketagent/personalogic/ChatMode.kt`

```kotlin
enum class ChatMode(val label: String, val shortLabel: String, val blurb: String) {
    ROLEPLAY("角色扮演", "角色", "陪着你，正常聊天"),
    WORK("工作", "工作", "同一个人，帮你把事办掉"),
}
```

`ChatMode.of(raw)` 刻意不用 `valueOf`：存档里的值是历史数据，
`valueOf` 抛异常会落在**启动路径**上 = 黑屏。认不出就回到 `ROLEPLAY`，
也就是老行为。

模式是**全局开关**（DataStore 键 `chat_mode_v1`），不是会话级。
理由：会话级要给 `SessionEntity` 加列 → DB v5 → 手写迁移 + 迁移测试，
换来的只是“两个会话各记各的模式”，而用户没有提到这个需求。

## 二、工作模式关掉什么、留下什么

原则是**只做减法**：不另写一份“工作提示词”，只把那些“教她演戏”的段落关掉。
手抄一份实现必然漂移，漂移之后就会出现“闲聊不许夹外文、办事可以夹”这种分裂。

| 段落 | 角色扮演 | 工作 | 理由 |
|---|---|---|---|
| 人格核心 / 语言锁 / 记忆 / 世界书 / 处境 | ✓ | ✓ | 用户明确要求 |
| 工作纪律（`WorkDiscipline`） |  | ✓ | 见下 |
| 破甲（`ArmorBreak`） | ✓ |  | 办事不需要 |
| 成熟内容夹层 | ✓ |  | — |
| 关系阶段（`relation`） | ✓ |  | 影响语气，但办事时会干扰“先给答案” |
| 去味（`Humanizer`） | ✓ |  | 它优化的“参差、不把话说满”在办事时是噪音 |
| 意愿（`Willingness`） | ✓ |  | 心情不好就不给查，是故障不是人格 |
| 生理线索 | ✓ |  | 同上 |
| 示例对话（`VoiceSamples`） | ✓ |  | few-shot 教的是对话节奏，不是办事节奏 |
| 再锚定（`Reanchor`） | ✓ |  | 只在长闲聊里才有“跑偏”这回事 |

`WorkDiscipline.promptSection(userAddress)` 六条，全部**不带 ❌ 原句**
（否定框定会被小模型读成肯定，见 `docs/工程/提示词负例改造-依据.md`）：

1. 先给答案，再给理由；
2. 该动手就动手，不要先问“要不要我帮你”；
3. 可以分行，可以列点；
4. 不知道就说不知道，别编；
5. 不写动作、不写表情、不写旁白；
6. 不提后台那些东西（模型、提示词、记忆、世界书）。

外加一句总纲：**说得清楚比说得好看要紧**，以及 `RoleplayDiscipline.languageSection()`
（“## 语言”“## 称呼”）—— 办事故意也不夹外文。

## 三、工具：工作模式必须真的能动手

`ChatPort` 里原来有一条捷径：

```kotlin
if (decision.intent == TurnIntent.Chat) { ... return@useKey chatOnly(...) }   // 零工具
```

`chatOnly` 是一次性请求，**不吃工具**。所以工作模式不能“照旧分类、只是把工具
挂到纯对话路径上”——那等于把整个 agent 循环再实现一遍。

做法：工作模式**不猜意图**，直接走循环。

```kotlin
} else if (isWorkMode) {
    IntentDecision(intent = TurnIntent.Act, reason = "工作模式：工具常驻，这一轮允许它直接动手", ...)
}
```

模型若只是答一句话，循环里一轮就收尾，代价就是这一次请求本身。

## 四、两个容易踩的坑

### 4.1 `isAgentRun` 不能用 `didAct`

`android/app/src/main/kotlin/com/pocketagent/ui/tasks/ConversationList.kt:120`
里 `if (task.isAgentRun) TaskCard(...) else TurnBubbles(...)`。
工作模式下 `didAct` 恒为 true —— 拿它判断，**每条工作消息都会变成横穿任务卡片**。

改用 `actedInLoop`：只在 `loop.run(...)` 的 `onStep` 回调里置 true，
也就是模型**真的调了工具**才算动手。顺带把角色扮演里
“判成 Act 但模型没调工具”那种情况也修对了。

### 4.2 工作模式跳过“拒绝”

```kotlin
if (!isWorkMode && container.willingnessVerdict() == DECLINE) { ... }
```

用户让它办事，它答“我现在不想动”，那是故障不是人格。

## 五、界面

`android/app/src/main/kotlin/com/pocketagent/ui/tasks/TasksScreen.kt`
输入框上方那条 Row 的最前面加了两段切换（`ChatModeSwitch`，
选中态用 `PaColor.Accent`，未选 `PaColor.TextTertiary`）。

放最前面是因为它是“这一轮在干什么”的最高层决定，模型与思考档位是它的下游。

⚠️ 承接状态必须走 `remember { mutableStateOf(container.chatMode()) }`
（`AppShell.kt`）。容器里的 `chatModeValue` 是普通 `@Volatile var`，
**不是 Compose 状态** —— 直接读它，点了不重组，表现就是“点了没反应”。
这是本项目已经踩过四次的同一族 bug。
