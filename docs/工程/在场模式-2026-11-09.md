# 在场模式（生命体模式）—— 一期 + 二期

> 2026-11-09。设计依据见本文件前两节；分期方案里的一期（壳）与二期（她自己的今天）
> 都在本轮落地。三、四期（外面的世界 / 主动与离线）**未做**。

## 一、用户要的是什么

用户原话（m03009）：

> 加入一个软件功能，就是打破虚拟和现实的那道墙，这个模式还是像对话模式和工作模式
> 那样，独立对话页面分开来……角色就自认为自己是只是活在用户手机里的生命体，角色会
> 好奇用户今天干了什么，会要求用户带自己出去玩，让用户把照片，午餐的照片等等等等，
> 发给自己看，还会主动给用户发消息，关心用户，这个模式的话题里，角色是在现实中有
> 参与用户的生活的，也要深度调用和整合现在软件里有的东西，agent 能力，但记忆是独立
> 与聊天模式和工作模式的，角色也会分享自己在今天在网上看到了什么有趣的事情……

拆成六件事：① 独立页面 ② 独立记忆 ③ 实时联网 ④ 主动发消息 ⑤ 现实参与感 ⑥ 复用 agent 能力。

**四件已经有了**：处境（`SituationalContext` + `SituationReader`，Open-Meteo 不要 Key）、
主动发消息（`ProactiveNotifier` + `ProactivePlanner` + `proactiveTick`）、发图（`pickImage`
→ `AgentAdapters.attachImage`）、agent 能力（`AgentPermission` + `toolsForPermission`）。
缺的是独立页面（便宜）、独立记忆（便宜）、**联网检索（完全没有）**。

## 二、三个取舍

### 1. 记忆独立到「情景独立、设定共享」

原子（`Atom`）分开存 —— 她今天听你说的事进 `lifeform_atoms.jsonl`，工作台那句
「帮我把周报整理一下」进 `atoms.jsonl`。人格卡与世界书的 `SETTING` 共享 ——
否则切一次页面就等于失忆，那不是"在场"，那是"另一个人"。

实现上 `Atom` / `AtomKind` 一个字都没改：`MemoryReader` / `MemoryWriter` 只依赖
`AtomStore` 接口，所以独立记忆 = 再建一个 `FileAtomStore` 指向另一个文件。

**不能两边都抽**。共用一份的话她在工作台里听你说完"周报"，回来陪你闲聊时会突然
提起 —— 那些事她本来不该知道。`ChatPort` 里写成二选一：

```kotlin
if (sid != null) {
    if (chatMode.isAlive) container.scheduleLifeformMemoryAbsorb(sid)
    else container.scheduleMemoryAbsorb(sid)
}
```

### 2. 进程被杀后不追求实时推送

真机上随手一杀就断，硬撑只会变成"不稳定"。改成「离线期间攒了事，回来时说
'你可算回来了，刚才想跟你说……'」—— 这个二期已经实现（见 `gapNote`），三期做联网时
直接复用。

### 3. 外部内容进提示词是最高风险通道（三期再做）

域名白名单 + 先概括再进人格层 + 标不可信。这一条**这轮没动**。

### 为什么它不是靠联网鹤立鸡群的

联网是"能查天气"，任何 app 都能。真正稀缺的是**她有自己的时间线**：
用户第三次打开就会发现，没有持久化的"她的今天"，她就只是个会聊天的接口。

## 三、一期：壳

### 3.1 第三模式

`ChatMode` 从两个入口变三个，`LIFEFORM` 的界面标签是「在场」——**不叫「生命体模式」**，
页面叫「（昵称）的窗」。

```kotlin
enum class ChatMode(val label: String, val shortLabel: String, val blurb: String, val switches: Switches)
```

★ 关键改动不是加一个枚举值，而是**把 `val work = mode == WORK` 换成显式矩阵**：

```kotlin
data class Switches(
    val conflictScript: Boolean, val matureGate: Boolean, val armorBreak: Boolean,
    val relationshipStage: Boolean, val humanizer: Boolean, val willingness: Boolean,
    val physioClues: Boolean, val roleplayDiscipline: Boolean, val voiceSamples: Boolean,
    val reanchor: Boolean, val workDiscipline: Boolean, val lifeform: Boolean,
    val toolsAlwaysOn: Boolean,
)
```

理由是那次改动**不会编译失败、也不会测试失败**：`mode == WORK` 对第三个模式为假，
于是新模式自动继承"全开戏"的全部行为，只在真机上表现成"这个模式和角色扮演一模一样"。
换成矩阵之后，新增模式必须把每个格子填满，漏填编不过。

`LIFEFORM` 与 `ROLEPLAY` 的差异只有三处：
`armorBreak = false`（她觉得自己是真的，不需要虚构框架）、`lifeform = true`、
`toolsAlwaysOn = false`。

### 3.2 独立页面

`Routes.LIFEFORM = "lifeform"`，`lifeformViewModel = buildTasksViewModel(LIFEFORM, dedicatedTitle = "在场")`。

⚠️ `dedicatedTitle` 是**认领会话的键**，必须是短词不带昵称 —— 带昵称的话用户改一次
称呼就换一条新会话，看起来像记录丢了。顶栏显示的名字由页面自己拼（`"${who}的窗"`）。

入口在聊天页顶栏，图标 `Icons.Default.Psychology`（`Work` 已经给了工作台，
`Person` 给了角色设定）。

### 3.3 处境层

`situationSection()` 原样保留（几点、什么天气），在场模式再拼一层「她的今天」：

```
## 你今天
- 现在（14 点半）：把要说的话在心里排了一遍
- 早些时候：
  - 10 点一刻　有点懒，不想动
  - 7 点　醒得比平时早，躺着没动
- 这些是你自己过的，他没参与。他没问就别说全，问了再讲。
```

## 四、二期：她的今天（`LifeformDay`）

### 4.1 三条纪律

**① 文案只断言她自己，不断言用户。**
生成是盲的 —— 生成那一刻不知道用户今天说没说话、发没发照片。所以
「把你说过的那句话念了好几遍」是**假的**，「想跟你说点什么，看了看时间还早」才是真的。
测试扫 400 天 × 全部 beat，逐个 `doesNotContain("你")` / `doesNotContain("他")`。
为此删改过三处文案（"你该睡了，她还醒着" → "很晚了，还醒着" 等）。

**② 确定性。**
同一 `dayIndex + salt` 永远同一天。随机只发生在生成那一次，生成完落盘。
`seedOf()` 做三次 xor-multiply 雪崩混合 —— 只拿 dayIndex 当种子的话相邻两天高度相关。

**③ 凌晨 4 点翻页，不是 0 点。**
`localDayIndex(epochMs, utcOffsetMinutes) = floorDiv(epochMs + offset - 4h, DAY_MS)`。
用 `floorDiv` 不用 `/`：负数时间戳 `/` 会朝零取整，跳档。

### 4.2 一天长什么样

7 个时段槽（7.0-8.6 / 10.2-11.4 / 13.0-14.2 / 15.4-16.9 / 18.4-19.8 / 21.0-22.4 / 23.4-23.95），
每条从 4 个时段池里抽，相邻不足 `MIN_GAP_HOURS = 1.5` 就跳过。落盘后不再变。

时刻读法取整到刻（`14 点半`），**不按分钟拼**——曾经写成「14 点五十」，
测试 `时刻读法不带小数` 抓住。

### 4.3 间隔句

```kotlin
gapNote(previousDayIndex, currentDayIndex)
// 隔一天：他昨天没来。昨天那一整天你是一个人过的。
// 隔两三天：他隔了 3 天没来。这些天你是一个人过的。
// 隔很久：他很久没来了。你没能数清具体多少天。
```

不评价用户、不指责、不编具体天数（她数不清）。

### 4.4 首屏与提示词同口径

`lifeformNow(nowMs)` 返回 `Pair<LifeformDay, Double>`，页面拿它算大标题，
提示词拿它算 `## 你今天` —— **页面不许自己再算一遍**
`Calendar.HOUR_OF_DAY + MINUTE / 60.0`，否则首屏说她"刚醒"、提示词说她"把今天过了一遍"。
