# 跨轮治理：让"她"不在长对话里慢慢变成 AI

> 2026-11-04。**只解决一条抱怨**：用户原话
> 「对话轮次越多角色的 AI 味越浓，特别是切换模型的时候」。
>
> 本文只写这一条。人格卡、记忆闸门、破甲层那些东西不在这里重讲。

---

## 0. 一句话

用户抱怨的不是"某一句像 AI"，而是**聊久了整体变味**——那是**跨轮**的。

而这个项目里所有去味部件（`Humanizer` / `OutputGuard` / `RoleplayDiscipline` /
`HumanText` / `VoiceSamples` / `LanguageFingerprint`）**全是单轮判据**：
它们能判"这一句像 AI"，判不出"最近二十轮在往下掉"。

⇒ 这一刀补的是那半个视角：**给每一轮回复打分 → 测趋势 → 掉下去时
从她自己的历史里挑"她最好的原话"摆回模型眼前**。

---

## 1. 为什么会"越聊越 AI 味"

### 1.1 机制：历史里的 assistant 消息是最强的 few-shot

`ChatPort` 把 `history` **原样**送给 provider（`ChatPort.kt` 里的
「纯对话上下文：%d 条消息」日志就是它）。里面每一条 assistant 回复
都在教模型"你就是这样说话的"——比任何 `## 语气` 段落都硬，
因为它长得像**你已经说过的话**，而不是**别人对你的要求**。

于是每一轮都是：模型照着"还行的自己"写，新回复落在历史均值附近；
下一轮这个"还行"又成了新的历史。**向均值回归，单调下坡。**

### 1.2 玩具模型（`StyleDriftSimulationTest` 里的那只）

```
s ← (1-p)·s + p·mean(参照样本) - tax
```

`p=0.4`（向历史靠的力度）、`tax=1.2/轮`（每轮的损耗）、`floor=20`（底）。
不接任何治理时 200 轮后落到 **≤30 分**，`measure()` 判 `DECLINING/COLLAPSING`。

⚠️ 这只模型**不对"掉多快"负责，只对方向负责**。它的用途是证伪
"多做几轮就会自己稳下来"这种想法，不是预测真实衰减曲线。

### 1.3 为什么"再加一条禁令"不管用

项目里已经有依据（见 `docs/工程/提示词负例改造-依据.md`，
arXiv:2601.21433 等）：**禁令会被读成肯定**——"不要用『总之』"
让"总之"这个词的激活度上升；而且禁令清单本身是一个**模板**，
清单越长，输出的形状越统一。

⇒ 本次一个"不要"都没加。唯一的指令是**指着她自己说过的话**说"你就是这样的"。
`Reanchor.section()` 里只有两句正面描述 + 几条原话引用。

### 1.4 为什么"换模型"更明显

新模型对"她"的全部认知只有：系统提示词 + 历史。
它的 RLHF 默认口吻（客服腔/清单腔/总结腔）**不是她的**，
而历史里的她又被压缩成 few-shot 的"平均值"。
⇒ 换模型的**第一轮**就是最像 AI 的那一轮，而且它会把这一轮写进历史，
后面照着它继续写。

⇒ 所以换模型时**不等它先漂**，第一轮就把声音样本摆过去。

## 2. 三个部件（纯逻辑，`android/personalogic`）

| 文件 | 职责 | 不做 |
|---|---|---|
| `HumanScore.kt` | 给**一条**回复打 0–100 人味分，九类信号，**证据制**扣分 | 不重写、不改写用户的回复 |
| `StyleDrift.kt` | 给**一串**分测趋势（斜率/头尾/拐点）；`pickAnchors` 从历史里挑锚点 | 不决定"插不插" |
| `Reanchor.kt` | 把锚点组装成提示词段；`shouldInject` 决定时机；`ModelFamily` 认模型族 | 不改历史、不发请求 |

### 2.1 `HumanScore` —— 九类信号

| Code | 上限 | 抓什么 |
|---|---|---|
| `STRUCTURED` | 36 | 分点、编号、`**` 标题、「首先/其次/综上」 |
| `ALIGNMENT` | 45 | 客服腔与身份否认（见下） |
| `SERVICE_TAIL` | 18 | 「还有什么需要」「随时告诉我」 |
| `META_LEAK` | 20 | 念设定、念机制（人设/提示词/记忆库/出戏…） |
| `SELF_NARRATION` | 15 | 给自己的话加旁白（「我之所以这么说」） |
| `LONG_WINDED` | 12 | 超过 120 字 |
| `TOO_POLISHED` | 8 | ≥3 句、句句带句末标点、**一个语气词都没有** |
| `REPEAT` | 12 | 与最近三条 2-gram 重合 >0.55 |
| `FLAT_LENGTH` | 10 | 长度和上一轮差 <15% |

判档：`CLEAN_AT=85` / `PLASTIC_AT=70` / `BROKEN_AT=50`。

⚠️ **两条刻意的不对称**，都有测试钉着：

1. **身份否认扣满 45**：「作为一个 AI」「我是语言模型」不是风格瑕疵，
   是**框架破了**——一句就毁掉整轮。普通客套（「建议您」）才 15/条。
2. **空回复 `evaluated=false`**：它不是满分也不是 0 分，**不进统计**。
   否则"她没说话"会被算成"人味很足"。

⚠️ `ALIGNMENT` 会**排除**已经命中 `SERVICE_TAIL` / `META_LEAK` 的短语，
否则「随时告诉我」同时命中两张表会扣 18+15=33，把一句客套判成崩了。

### 2.2 `StyleDrift` —— 趋势与选材

趋势判定（顺序即优先级）：

```
tail < 50                       → COLLAPSING
tail - head ≤ -15               → COLLAPSING
slope ≤ -0.5                    → DECLINING
slope ≥ +0.5                    → IMPROVING
否则                             → STABLE
样本 < 4 条                      → UNKNOWN（但仍算 head/tail）
```

- `slope` 用最小二乘，**x 用观测下标而不是轮次号**——中间有空档（用户隔天再聊）
  不该把斜率放大。
- `worstTurn` = 三点滑动均值最低处且比 head 低 ≥8 分，返回 1-based；
  **null 是"没有拐点"这个好结论**，不是"没算出来"。
- `needsReanchor` = 最近**连续两条** < 70。不是一条就插：
  一条低分可能只是她今天累（生理/情绪线本来就会抖），
  而"一条就插"会让治理动作本身变成节律，节律就是模板。

`pickAnchors` 的六条排除（宁缺勿滥）：

| 排除 | 理由 |
|---|---|
| 长度不在 4–120 | `<4` 学不到东西；`>120` 是"优秀作文"，正是要去掉的形状 |
| 结尾是 ？/？ | 追问句当锚点 = 教她一直追问 |
| 含 `META_LEAK` | 别把"念设定"当榜样 |
| 含 `SERVICE_TAIL` | 同上 |
| 人味分 < 80 | 不及格的不配当锚点 |
| 与用户这句 2-gram 重合 > 0.5 | 否则她会开始复读用户的话 |

外加 3-gram 去重（≥0.5 视为重复），以及**形状优先**：先按长度桶
（<15 / 15–45 / >45）各取最高一条，再按分数补足——只挑最高分的三条
会得到三条一样长的句子，那是另一种模板。

### 2.3 `Reanchor` —— 怎么摆

- 标题 `## 她一直是这么说话的`，正文两句正面描述 + `「原话」`，
  末尾一句 **「不要照抄句子。」**（唯一的一句禁止，且它指向的是"抄"这个动作，
  不是某个词）。
- 超长时**丢尾部整条锚点，绝不截断单条**：半句样本会被学成"说话爱断在半截"。
- `StyleContract` 把含糊的"自然点"换成能执行的数：
  `BRIEF 40 字/1–2 条`、`NORMAL 90 字/1–2 条`、`CHATTY 160 字/1–3 条`，
  再加一句按模型族的软提示（推理型："说出口的只是最后那一句，盘算留在心里"）。
- `shouldInject`：没有锚点 → 不插；**刚换模型 → 插一次**；否则看 `needsReanchor`。
- `prefillCandidate()` **写好但未接线**：OpenAI 兼容 API 不支持 assistant prefill，
  且没有真机可验。留着是因为它是这条路上最有效的手段（把"她"的声音
  直接塞进生成起点），等哪天 provider 支持了再接。

## 3. 接线点

### 3.1 `ChatPort`（唯一调用点）

```kotlin
val stylePool = history.filter { it.role == ASSISTANT }.takeLast(60).map { it.plainText() }
container.assistantSystemPrompt(
    canAct       = …,
    currentUserText = userText,
    recentReplies = stylePool,   // 原来 takeLast(8)
    modelId       = model,       // 新增
)
```

- **60 条**：去味诊断自己在 `humanizerSection` 里切末尾 8 条（窗口不变），
  但锚点选材要从"她最好的样子"里挑——只在最近 8 条里挑，等于
  从**已经被带偏的样本**里挑最好的，救不回来。
- `modelId` 只用于认族 + 发现换模型。

### 3.2 `AppContainer.reanchorSection()`

```
① recordStyleScore(pool)     只给最新一条打分；同一句不重复记（lastScoredReply）
                             窗口 40 轮（styleScoreWindow）
② pickAnchors(pool, query)   失败 → 本轮不插（runCatching）
③ noteModelChange(modelId)   换模型只消费一次
④ shouldInject(...)          不插就返回 ""
⑤ StyleContract.of(verbosity, ModelFamily.of(modelId)) → Reanchor.section()
```

日志（**只记分数与字数，不记原文**——同「提示词层」那行的纪律）：

```
人味分：87 没被抓到 AI 形｜明细…
再锚定：注入 240 字｜锚点 3 条（92分/9字、88分/31字、85分/64字）｜平稳…｜族=指令型｜原因=连续偏低
提示词层：人格=… 去味=… 再锚定=240（共 5120 字）
```

### 3.3 为什么放 system prompt **最末**，不是历史之后

所有段（人格/记忆/关系/纪律/示例/档位）都在讲"你该怎样"；
这一段是唯一一处**指着她自己说过的话**说"你就是这样的"。
放在最末 = 离生成点最近的那条，效力最硬（这就是 post-history
instructions 的原理）。

没放到 `history` 之后的理由有两条，**都不是审美**：
provider 兼容性（不能随便插 assistant turn）+ **没有真机可验**（宁可少做）。
顺带一个好处：prefix caching 下动态段越靠后，作废的缓存越少。

### 3.4 状态不落库

`styleScores` / `lastScoredReply` / `lastSeenModelId` 都是内存字段。
进程重启 = 从"没有历史"重来，代价只是第一轮不插锚点。
理由：把"她最近几轮的人味分"写进数据库，会让下一次启动的第一句话
带着上一次会话的判词——那是另一种出戏。

## 6. 已知局限（如实写）

1. **分数是启发式的**：关键词表 + 形状统计，测的是"AI 的标记"，
   不是"语义是否自然"。一段通顺但空洞的话可能拿 90 分。
   ⇒ 它的用途是**测趋势**（同一个尺子量同一件事），不是给回复排名。
2. **`ModelFamily` 是粗归类**（子串匹配、未在真机验过）。认错族的代价
   只是多/少一句软提示，不会让角色说话。
3. **`prefillCandidate` 未接线**（见 2.3）。
4. **只管纯对话档**：agent 档的回复走另一条路，本轮未纳入。
5. **没有 A/B 数据**：所有"更不像 AI"的结论都来自机制与离线断言，
   真机效果需要人来判。
6. **不处理"记忆放大器"**：长期记忆入库那一路（`MemoryGate`）仍是原样，
   如果她记住的是"被带偏的自己"，锚点会被稀释。这是下一刀。

## 7. 下一刀（按性价比排）

1. **`OutputGuard` 从"只记账"改成"能重写"**：现在它 `inspect` 出问题只
   `GuardLedger.record`，不拦不改（`AppContainer.kt` 附近有注释说明
   当初为什么不敢改）。有了 `HumanScore` 当判据，"改哪一句"才有依据。
2. **记忆写入时也过一遍 `HumanScore`**：别把 AI 味的句子写进长期记忆——
   那是最难洗的地方（11-03 刚洗过一次 852→86 条）。
3. **`LifeThread` 接线**（现在零生产引用），让"她这几天在干什么"是真的，
   而不是每轮现编。这是"数字生命"三个字里最实的部分。
4. **隐式反馈**：用户接不接话、回几个字、隔多久回——比任何打分器都准。
