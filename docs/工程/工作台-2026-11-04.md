# 工作台（独立的干活页面）—— 2026-11-04

> 用户原话：“工作模式你要切到另一个页面啊，就是工作页，在这个页面，开场，背景上
> 都会有这个角色的随机开场白，像 claude 那样，这个页面就叫「（用户对角色的昵称）
> 的工作台」而不是从角色聊天切换到工作，这样太生硬了。”

三个要求，三条实现：

| 要求 | 落点 |
|---|---|
| 独立页面，不是聊天页的一个状态 | `Routes.WORKBENCH` + 独立的 `TasksViewModel` |
| 随机开场白，像 Claude 首页 | `WorkbenchGreeting`（文案，有测试）+ `WorkbenchHero`（画） |
| 标题是「（昵称）的工作台」 | `TasksScreen(pageTitle = …)`，昵称取 `addressSelf`，退回 `name` |

## 一、为什么必须是独立页面

同一个页面里换模式，用户看到的还是一个**装着 207 条私密历史的对话框**，
只是顶上多了个“工作”标签。她会在这里继续说“你回来啦”，而用户想的是“帮我订张票”。

独立页面最直接的好处是**空**：空白 + 一句报到 + 一个输入框。
“空”本身就在说“这里不谈那件事”。

代价是两份 `TasksViewModel`，各自一条消息列表。这是刻意的：
一份 `mode = ROLEPLAY`，一份 `mode = WORK`，模式由构造函数注入，
`ChatPort.send(mode = …)` 每轮都带着它 —— 不靠全局可变状态猜“现在是哪个模式”。

## 二、工作台有自己的会话（但不动全局指针）

`TasksViewModel(mode, dedicatedTitle = "工作台")` 在首次进入时：

```kotlin
store.recentSessions(SESSION_LIST_LIMIT).firstOrNull { it.title == dedicatedTitle }
    ?: store.newSession().also { store.renameSession(it.id, dedicatedTitle) }
```

**刻意不写 `currentSessionId`。** 那个字段的语义是“下次冷启动打开哪一个”，
是全局的。工作台把指针挪走之后，用户从后台切回来会直接掉进工作台，
而不是回到正在聊的那一段 —— 那不是“分家”，那是“抢房间”。

### 为什么不用同一个会话（考虑过）

共用会话 + 工作台只显示 `mode == WORK` 的消息，看似省一次迁移，但：

1. 角色扮演那 200 多条历史仍然在同一个 `sessionId` 下，
   任何“导出一段对话”“按会话删记录”的功能都会把它们一并带走；
2. 开场白**永远不会出现** —— 列表非空，空态分支根本不进。

第一版就是这么写的，装机后发现工作台一进去就是满屏旧对话，
星芒和开场白连一次都没露过面。所以改成认领独立会话。

## 三、开场白

`android/personalogic/src/main/kotlin/com/pocketagent/personalogic/WorkbenchGreeting.kt`

- **四段**（早 / 白天 / 晚 / 深夜），分段点选在作息边界（5:00 / 11:00 / 17:00 / 22:00），
  不是整点 —— 没人觉得“12 点整开始算下午”。
- **纯函数 + 显式 `seed`**：不在里面读时钟或 `Random`。
  同一时刻 + 同一颗种子永远同一句，可回放、可测。
  真机上“每次进页面换一句”由调用方传 `System.currentTimeMillis() / 60_000` 实现
  —— 一分钟内连按两次拿到同一句，隔一会儿进来就换一句，这正是“随机”的节奏。
- **三条硬约束**（有测试钉着）：不许撒娇（“人家等你半天了”会让用户怀疑这页又要陪聊）、
  不许动作描写（工作模式不写 `（）`，见 `WorkDiscipline`）、不许超过 24 字。
- `CALL = "{call}"` 显式占位，**不用 `String.format("%s")`**：
  用户把称呼写成 "100%不靠谱" 时，格式化会直接抛
  `UnknownFormatConversionException` —— 一句开场白把页面搞崩。

### ★ 真机事故：整段人格说明被当成称呼喊了出来

第一版把 `CustomPersona.addressUser` 原样塞进 `{call}`。装机后大标题是：

```
她通常称呼你“主人”或直接叫“你”。婚后会更习惯叫“老公”“亲爱的”
在照顾你、哄你或表达温柔时，偶尔会用带着宠溺意味的语气叫你“乖一点”“小笨蛋”，
但不会每句话都使用昵称。……，还没睡？说吧。
```

根因不是代码写错，是**字段语义读错**：`addressUser` 的标签是“怎么称呼用户”，
但用户填进去的是一整段说明文字。这类字段天然会被填成描述段落。

修法是 `salutationOf(raw)`：只有“看起来像称呼”才放行，否则返回空串，
退回**不带称呼**的那一组文案（不是把“你”硬塞进 `{称呼}，早` 变成“你，早”）。

判定顺序：

1. 去首尾空白后为空 → 弃；
2. 长度 > 8 → 弃（一个称呼喊出口最多几个字）；
3. **有任何一个字符不是字母（含汉字）→ 弃**；
4. 含「称呼 / 叫 / 通常 / 有时 / 习惯 / 语气 / 亲密 / 亲昵 / 昵称」→ 弃（在解释自己）。

第 3 条原本写成**黑名单**（列举 `，。“”（）` 等），第一版跑测试时立刻漏了 `/`：
「主人/亲爱的」照样整段喊了出去。标点的变体永远列不完 ⇒ 改成“非字母即拒”。

**教训**：这类“字段名字短、内容长”的输入，校验要按**形状**（字母/长度/无元叙述）
判，不要按字符表判；而且**必须在真机上目视一次** ——
这一条任何离线测试都不会替我发现，是装机后一眼看出来的。

## 六、2026-11-04 晚（二）：图标、话、居中、工作区 / 权限

用户看完第一版真机截图后提了四件事，逐字：

> 「claude的图标你不要照搬呀，还有，那句工具链已经挂好，你说，我做，换掉换掉，
> 换成角色自己的话。还有，要居中，另外，在工作区，模型选择的旁边加上工作区选择，
> 还有权限选择，这两个照搬电脑上的harness命名就好了」

### 1. 图标：星芒 → 一张台子

八向星芒是 **Claude 的图标**。照搬它，是把「像 claude 那样」误解成了「变成 claude」。

换成三条线：一块台面、一条腿、一条底座 —— 正好就是「工」。
它同时回答了*这页叫什么*（工作台）和*这页干什么*（干活），而且歪打正着地像一件家具。

`WorkbenchMark` 仍然用 `Canvas` 画（三条线而已，位图/矢量资源在深浅色主题下要各带一份，
而且没法跟着强调色走）。台面比底座宽一点 —— 一样宽就只是「工」字，不是桌子。

### 2. 小字：从"安装日志"换成她说的话

上一版整池里最刺眼的一句是「工具已经挂好了。你说，我做。」

问题不在措辞好不好听，而在**说话的人是谁**：
「工具已经挂好了」是**安装日志**在说话，「你说，我做」是**任务队列**在说话。
这行小字长在**她的**页面上、就在她的开场白下面，说话的必须是**她**。

⇒ 整池换成第一人称口语（「说吧，我这就去看。」「慢慢来，我不催你。」…）。

两条新测试钉住它，而且钉的是**永远不会变的东西**：
- `小字里不许出现机器腔的词`：整池扫「工具/挂好/权限/模型/系统/已启用/加载」；
- `小字每一句都有第一人称`：每句都得含「我」——上一版那句两样都不占，正好被抓。

### 3. 居中：`weight(1f)` 不等于满宽

真机截图量出来的（1440×3200）：星芒中心 x=417、大标题 400、小字 401，屏幕中心 720 ——
**横向偏左约 320px**；纵向 1584 恰好是内容区中心，本来就是对的。

根因在 `TasksScreen.kt` 的 `Box(modifier = Modifier.weight(1f))`：只写 weight 时
Box 的宽度 = 最宽那个子项的宽度。列表有内容时 `LazyColumn` 撑满，看不出问题；
空态时子项是开场白那几行字（不到 400px），于是 Box 跟着变窄、被 Column 靠左摆 ——
`Modifier.align(Alignment.Center)` 只是**在这个变窄的 Box 里面**居中，等于没居中。

改成 `Modifier.weight(1f).fillMaxWidth()`。修完复量：星芒 668..772 → 中心 **720**。

> **教训**：`weight` 分的是"剩余空间"，不是"父容器宽度"。父容器里没有横向约束时，
> 子项宽度由内容决定，而 `align(Center)` 只在**自己的**范围内居中。
> 这类 bug 在列表非空时完全看不见，**只有在空态才暴露** —— 而空态恰恰是用户第一次进来看到的那一屏。

### 4. 工作区 / 权限：两颗 chip，而且真的接线

命名照搬电脑端 harness：`read-only` / `workspace-write` / `danger-full-access`
→ 只读 / 工作区可写 / 完全访问。判定在 `:agentlogic` 的 `AgentPermission.allows(effects)`。

三条设计约束：

1. **按效果判，不按工具名。** `allows` 的输入是 `ToolSpec.effects`。手工白名单的
   失效方式是"新加一个工具、忘了同步，它被静默归到某一档"—— 而静默归类在这里
   等于"用户以为自己只开了只读"。没登记的工具一律不给。
2. **手机上的取舍**：点屏幕（`MOVES_SCREEN`）算进「工作区可写」（点错了能退回去）；
   发消息 / 改系统设置（`SENDS_TEXT` / `WRITES_SYSTEM`）不可撤销，才要「完全访问」。
3. **只在工作台生效。** 聊天页传 `null` —— 角色扮演里没有"权限"这回事，
   给她一句"你现在是只读"会让她开始汇报工作。
