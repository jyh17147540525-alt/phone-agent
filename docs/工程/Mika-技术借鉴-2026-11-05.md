# Mika 逆向笔记：值得拿的机制，以及我们自己的做法

> 对象：GitHub `wangzan101/Mika`（2026-10-29 建，Apache-2.0，Kotlin/Jetpack Compose，
> 约 6.9k stars、1.5k forks，`app/src/main` 下 350 个 .kt）。
> 它的定位和我们几乎重合：**Android 上、靠无障碍 + 内置浏览器操作 App 与网页的 agent**。
>
> ⚠️ 本文只记**机制**。不复制它的代码、文件结构或文案 —— 我们的分层、命名、判断口径
> 都按本项目自己的约定重写；凡是"它的做法"都只作为**证据**（证明这条路在真机上成立），
> 具体实现见文末"我们怎么落"。

---

## 0. 它最强的三件事（不是功能，是结构）

1. **一个执行入口**：所有改变外部世界的动作都过 `ActionExecutor`，`ActionPass` 构造函数
   `internal`，只有它能造 —— 绕过守卫在**编译期**就不可能。
2. **工具按组收着、用到才展开**：开局只给每组一个"入口工具"，调用后才把整组工具与
   对应提示词段落拼进去；一个任务内提示词前缀最多只变几次，prompt 缓存因此基本不失效。
3. **观察（Observation）是唯一单位**：读屏、命令输出、网页正文、用户插话、附件、子任务结果
   全部先变成带出处/可信度/步数/编号的观察，再进证据账本；最终回答下面的"来源"由系统
   从账本里挑，**不由模型自己写**。

## 1. 逐项对照：它怎么做 → 我们缺什么 → 我们怎么做

## 2. 本轮已落：工具分组与按需展开（我们自己的实现）

**它解决的问题**：工具一多，提示词里那一大段工具说明每轮都出现，既挤掉真正重要的指令，
又让 prompt 缓存每轮失效（缓存按前缀算）。它的答案是"收起 + 入口 + 展开"。

**我们的设计**（`android/agentlogic/.../orchestration/ToolGroups.kt`）：

- `ToolGroup`：`BASE`（每轮都给：读屏、人格摘要、上下文搬运）、`UI`（点按/滑动/输入/按键/批量）、
  `SYSTEM`（root/文件读/改设置/改属性/停用应用）、`FILES`（授权目录里的文件操作）。
- 每组一个**入口工具**：`UI→android_tap`、`SYSTEM→root_exec`、`FILES→office_tools`。
  入口的说明写"这一步要干什么"，不写参数表。
- `ToolExplorer` 是一个**只开不合**的状态机：
  - `offer()` 给出本轮该给的工具：BASE 全部 + 每个未展开组的入口 + 已展开组的全部；
  - `onCall(tool)`：**即使模型凭记忆调了收着的工具，也照常执行并展开它那一组**
    （否则它会一直看不到参数表，只能瞎猜）；
  - `preloadFrom(goal)`：目标里出现"文件/表格/目录"就先展开 FILES，出现"root/设置/属性"就先展开 SYSTEM；
  - 一个任务内**永不收起**：前缀只增不改，缓存最多失效一次。

这样"手脚架必须全"和"提示词不能爆"不再冲突：能力全在目录里，但一次只把用得上的那一组
摊到模型面前。

## 3. 本轮已落：等待条件（纯逻辑）

`WaitCondition`（同包 `WaitConditions.kt`）：`TextAppears` / `TextDisappears` / `PackageIs` /
`Stable`（连续两次摘要相同）/ `ValueIs`，各带 `timeoutMs`（默认 8s、上限 20s）与一个
`check(digest, previous): WaitOutcome`（`Met` / `Pending` / `TimedOut`）。

**为什么值得抄这个机制**：模型说"点完等一下"，现在的做法是它自己再调一次 `screen_read`
猜"好了没"——一次 150–400ms 且要一轮模型往返（800–3000ms）。把"等"变成代码里的循环，
省的是**模型往返**，不是读屏。

## 4. 明确不借的东西

- 它的 `CapsuleController`（64KB）/ `CapsuleCardContent`（45KB）那套悬浮胶囊：我们的
  `:overlay` 是另一套设计，借了只会得到一个互相打架的第二套。
- 它的微信渠道、账号登录（ChatGPT/xAI/OpenRouter）、Token 用量统计：与"手机端 agent 能力"无关，
  属于产品面，不在这次范围。
- 它的四种模型协议适配器：我们已有 `:provider:*`，重复实现等于两套 URL/错误处理。
- 它的文件命名与包结构：照抄结构会让后来的人以为两个项目同源，改动时互相误导。
