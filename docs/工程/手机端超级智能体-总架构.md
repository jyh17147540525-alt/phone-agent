# 手机端超级智能体 —— 总架构

> 目标（用户原话，2026-11-04）：「用户一句话，就能下达指令和任务，自己跑通全流程」。
> 本文写**已经落地的那条链路**、**与电脑端三件套（Claude Code / Codex / DeepSeek Harness）
> 的逐项对照**、以及**还缺什么**。缺的部分单独列，不混进"已完成"。

---

## 1. 一句话进来之后发生了什么

```
一句话
  │
  ├─ ① 分流  TaskIntake（规则下限）+ 模型判定（正常路径）
  │    ├ Chat     → 交给聊天，agent 一步都不动
  │    ├ Clarify  → 先问一句（指代没上文、话没听清）
  │    ├ Task      → 单件任务
  │    ├ Chain     → 一句话里排着好几件事
  │    └ Stop      → 喊停
  │
  ├─ ② 规划  ModelPlanner → RunPlan（步骤 + 每步的验收条件）
  │
  ├─ ③ 执行  RunOrchestrator → 逐步调用 MCP 工具
  │    ├ 前置：确认闸（有后果且不可逆才拦）、预算（步数/时长/重规划）
  │    ├ 执行：McpStepRunner（超时、Refused/Failed 分流）
  │    ├ 验收：再读一次屏 → ScreenDigest → Expectation
  │    └ 失败：重规划 / 判打转 / 带失败提示收手
  │
  └─ ④ 汇报  SuperAgent.spoken → 一句人能听懂的话（+ trace）
```

每一层都能离线跑：`run_logic_tests.py` 里 `com.pocketagent.agentlogic.orchestration.*`
全部用剧本演（不需要真机、不需要模型）。

## 3. 与电脑端三件套的对照

| 能力 | Claude Code / Codex | DeepSeek Harness | 手机上的落法 | 现状 |
|---|---|---|---|---|
| 读文件 | 直接读 | 直接读 | `file_read`（root）/ `office_run`（授权目录） | 有 |
| 跑命令 | shell | shell | `root_exec`（黑名单）+ 通道 `EXEC`（白名单） | 有 |
| 改代码 | diff/patch | diff/patch | 无对应物 —— 手机上改的是**界面与设置**，不是源码 | 不适用 |
| 看屏幕 | 无 | 无 | `screen_read` / `screen_shot` / root dump | 有 |
| 点鼠标 | 无 | 无 | `android_tap` / `swipe` / `type` / `key` / `batch` | 有 |
| 计划-执行-验证 | 写→跑测试→看输出 | 同左 | `RunOrchestrator` + `Expectation`（验收读屏） | 有 |
| 子任务并行 | Task/agent 并发 | work item 并发 | 未做（当前串行链） | **缺** |
| 会话恢复 | 会话文件 | 自己的 session 目录 | `TaskCheckpoint` + 常驻通道 | 有（未真机验） |
| 权限模型 | 逐次确认 | 002-authorization | 档位网关 + 确认闸 + `AutonomyPolicy` | 有 |
| 预算 | token/时长 | token | `RunBudget`（步/时/重规划）+ `AgentBudget` | 有 |
| 插件扩展 | hooks/skills | 插件包（cordis） | `:plugin:api` 契约（`plugin:runtime` 为空） | **缺运行时** |
| 主动监听 | 无 | GitHub/飞书事件 | 无 | **缺** |

> 一句话总结这张表：**"看"和"动手"比电脑端更强（手机是唯一有真实副作用的终端），
> "并行"和"插件运行时"比电脑端更弱。**

## 4. 三条设计决定（以及为什么）

### 4.1 模型负责"想"，编排负责"查"

模型说"我做完了"不算数：每一步做完都要再读一次屏，拿 `ScreenDigest` 对 `Expectation`。
**代价**是每个带验收的步骤多 150–400ms。这个代价必须付 —— 不验就等于相信模型。

### 4.2 确认闸只拦"有后果的不可逆动作"

拦：改系统设置/属性、发出去的内容、写数据，且**不可逆**。
不拦：点屏幕本身（`android_tap` / `android_type`）。理由不是"点屏幕不可怕"，而是
**每一步都要确认的 agent 等于没有自主度** —— 用户会先去设置里把确认关掉，
那时候真正危险的动作也没人看了。闸门必须稀缺才有人认真读。

### 4.3 被拦下是最终结论，不许重规划绕路

`StepStatus.REFUSED` 直接收手。换个写法重试等于再撞一次同一道闸，
而日志里会看不出"到底谁在拦"。技术故障（超时、目标找不到）才重规划。

## 7. 已知缺口（按优先级）

1. **`:plugin:runtime` 是空的**。`:plugin:api` 有 `PluginManifest` / 校验 / 市场契约，
   但没有加载器 —— 插件工具进不了 `ToolCatalog` 与 `ToolGate`。这是"扩展空间"唯一的硬缺口。
2. **SuperAgent 没有流式回调**。`RunOrchestrator` 只在结束时给报告；长任务期间界面无进度。
   现有 `PhoneAgentLoop` 有 `onStep`/`onProgress`，两条路应当共用一套回调。
3. **验收只认屏幕**。文件写完、消息发出去、HTTP 200 这类"不在屏幕上"的结果验证不了。
4. **没有子任务并行/依赖图**。链条是串行的，且只做前 4 件。
5. **确认弹窗 UI 还没接**。`AWAITING_CONFIRMATION` 现在只体现为一句文字，
   用户没法"点一下继续"（`RunContext.confirmedStepIds` 已留好口子）。
6. **记忆/人格没进这条链路**。人格摘要、记忆注入仍然只在 `ChatPort` 的聊天路径里，
   SuperAgent 走的是纯任务路径 —— 用户在任务中听到的语气会与聊天时不一致。
