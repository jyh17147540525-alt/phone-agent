# 未接线清单（生产代码零引用）

> 生成于 2026-11-01。**这是一份待办，不是成就。**
>
> 本项目反复出现同一类缺陷：组件写完、测试绿、**生产代码零引用**。
> 之前是零散发现（`RelationshipStage`、`PaMotion.bouncy`、`PerceptionLadder`、
> `OutputGuard`、8 个 UI 组件、`shouldOfferHelp`、`StreamPump`…），
> 这次做了一次**系统扫描**。

---

## 怎么扫的（含一次方法错误）

```powershell
# 1) 收集全部生产源码（排除 test/ 与 build/）→ 333 个文件
# 2) 抓顶层 class/object/interface 声明 → 835 个
# 3) 对每个声明，在**其他生产文件**里搜名字
# 4) 按文件聚合：该文件**所有**声明都零引用 → 整文件死代码
```

### ⚠️ 第一版扫错了

我最初按"每个文件的**第一个**声明"判断整文件死活。结果把
`TaskDifficultyAssessor.kt` 判成死代码 —— 因为它的第一个声明是
`LocalAssessment`（一个 data class），而 `TaskDifficultyAssessor`
本身在 `ModelRouter.kt` 里被用了。

于是第一版报了 26 个，**其中 8 个是误报**：
`VirtualDisplayManager`、`AtomExtractor`、`LifeThread`、`PersonaAudit`、
`OfficePorts`、`TaskDifficultyAssessor`、`IconGeometry`（扫的时候确实没接）、
`AtomExtractor`。

⇒ 改成"该文件**任一**声明被外部引用即算活"，剩 **18 个**。

★ 教训：**审计工具本身也需要被审计。** 一份误报 30% 的清单没人会用第二次。

## 五、2026-11-01 发现的更严重情况：**契约有、实现无**

追 `AmbiguityResolver` 为什么没接线时，查出一件比"未接线"更严重的事：

**`AgentOrchestrator`（`:agent`）是一份完整契约，但零实现。**

| 契约 | 实现方 |
|---|---|
| `Grounder.locate(...)` | **没有任何类实现** |
| `Verifier.verify(...)` | **没有任何类实现** |

⇒ `GroundResult.Ambiguous(candidates)` 在运行时**永远不会产生**，
   所以"没人消费 `AmbiguityResolver`"不是接线问题 ——
   **是上游的 `Grounder` 根本不存在。**

⚠️ 我此前把它描述成"被离线验证盲区挡住"，那个说法**不准确**。
   真正的顺序是：先有 `Grounder` 实现，才谈得上消歧。

而 `OfficeAgentLoop`（`:agentlogic`）的类注释写得很清楚：

> ★★★ 它与 `:agent` 的 `AgentOrchestrator` 是**两条线**，不要合并

⇒ 办公这条线走的是自己的实现，不经过 `AgentOrchestrator`。

**结论**：`AgentOrchestrator` + `Grounder` + `Verifier` + `AmbiguityResolver`
这一整条「感知 → 定位 → 校验 → 消歧」链路**目前只是纸面设计**。
要它跑起来，得先写 `Grounder` 的实现（要用 `:perception` 的节点树）。

这一项不该留在"未接线清单"里 —— 它不是接线问题，是**未开工**。

## 六、2026-11-01：把剩下三项逐个判完

「零引用」有三种，处理方式完全不同。这一轮把清单里剩下三项都判清了：

### ① `AccentUsage` —— 不是未接线，是**审核口径**

它自己是这么写的：

> ★ 它不能真的去读 Compose 源码（那是编译期的事），
>   但它是**审核时的口径**：review 时按这个判据看，比凭感觉一致。

⇒ 口径的正确"落地"不是被调用，而是**被拿来量一次**。
本轮量了 `:app` 的 ui 目录里所有 `PaColor.Accent` 的非 AccentText 用法，
**没有违规**。最容易判错的四处结论已写进 `AccentUsage` 的注释。

与它同类：`MaterialMotion`（M3 token 参考表）、`IconGeometry`（尺寸档位表）。

⚠️ 把它们塞进"未接线清单"是**分类错误** ——
   会让下一个人去做无意义的接线工作。

### ② `PermissionPolicy` —— 未开工

`decide(risk, remembered)` 是「问用户要不要授权」的判定逻辑。
但**"问用户"的界面不存在**：没有 consent 弹窗、没有"记住这次选择"的存储。

⇒ 缺的不是接线，是一个界面。同 `Grounder` 当初的情况。

### ③ `MentionIndex` —— 未开工

`search(query, items)` / `grouped(...)` 是输入框里 `@` 提及的搜索与分组。
但**输入框没有 @ 面板**。

⇒ 同上，缺的是界面。
