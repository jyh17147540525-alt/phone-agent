# 「关于你」——用户档案页

> 2026-11-16。用户原话：「app少了一页内容，就是用户自己的设定和习惯这些，加入这个后能让角色更快地了解用户，不用经过多轮对话才能稍微了解一点用户」。

## 为什么需要这一页

角色的人格、身体、世界书全都是用户自己填的 —— 唯独**对面那个人**是空白。

于是每一段新关系都从同一句开始：

> 「你是做什么的？」

这句话不是角色笨，是她真的不知道。她只能靠一轮一轮的对话去猜，猜错三五次才碰到边。
用户填一次档案，她第一句就能站在「已经知道你是谁」的位置上说话。

## 这一页填什么

| 分组 | 字段 | 进提示词的样子 |
|---|---|---|
| 怎么叫你 | `callName` | 「叫「X」」——**角色设定里填了称呼时整行不输出** |
| 基本 | `gender` / `ageBand` / `livingWith` | 「三十几岁，一个人住。」 |
| 你在做什么 | `work` / `nowBusy` | 「工作：做后端的，天天加班。」「最近：在赶一个上线的版本。」 |
| 你怎么说话 | `chatStyle` | 「老板话少，累的时候只回一两个字。你也别追问，更别写长回复。」 |
| 喜欢与不喜欢 | `likes` / `dislikes` / `taboos` | 「老板喜欢冰美式、下雨天。」「别提上一份工作，也别提他前女友。」 |
| 身体上要知道的 | `bodyNotes` | 「身体：腰不好，坐久了要站起来。」 |
| 作息 | `sleepHour` / `wakeHour` | 「老板一般 2 点睡，9 点起。」 |
| 已经发生过的事 | `knownFacts` | 「你们之间已经发生过的：第一次见面在便利店；她记得他喝冰美式。」 |
| 补充 | `extra` | 「老板还想让你知道：不太会说漂亮话。」 |

刻意**不要出生年月**：这是「让角色了解你」，不是办证。

## 三个关键决定

### 1. 称呼以角色设定为准，档案让位

`CustomPersona.addressUser`（「怎么称呼你」）和档案的 `callName` 是同一件事的两种写法。
两份并存，模型一定会挑错一个。所以：

- `promptSection(callNameFromCharacter = …)` 收到非空值时，档案里那行**整行不输出**；
- 界面上那格改成一句只读提示，不再让用户填第二遍。

### 2. 超预算是整行删，不是截半句

`MAX_CHARS = 900`。超了就按优先级从低往高**整行**删：

```
0 雷区与称呼（永不删）  1 说话习惯  2 工作·最近  3 年龄与同住
4 喜欢不喜欢  5 身体  6 作息  7 既成事实  8 补充
```

截半句的后果比删一行严重得多 —— 「他腰不好，坐久了要站」会被模型当成完整事实继续用。

### 3. 小时用 `Int?`，0 点是有效值

`sleepHour = 0` 是「十二点睡」的真值，不能拿 0 当「没填」。
存储层因此把小时写成字符串（`""` 才是没填），反序列化用 `toIntOrNull()`。

装配位置有一处必须记住：**要放在自定义角色那一支之外**。
自定义角色整条绕开 `PersonaAssembler`，档案要是只接在装配器那条路上，
用了自定义角色的用户就一个字都拿不到 —— 和 `PromptRoles.settingHeader()` 是同一个坑。

## 提示词的形状

```
## 关于他

这些是他自己填的，都是真的。

叫「老板」，三十几岁，一个人住。
工作：做后端的，天天加班。
……
这些你已经知道，别再从头问一遍。
```

首尾两句是框定，不是客套：

- 「这些是他自己填的，都是真的。」—— 防她把档案当剧情素材演。
- 「这些你已经知道，别再从头问一遍。」—— 防她逐条盘问（模型看到条目的本能反应是问）。

整段必须过 `PromptVoice.audit` 体检（无列表符、无加粗、无破折号、无元话语、无排比口号），
否则那段腔调会传染到她的正文里去。已登记在 `PromptVoiceTest.productionSections()`。
