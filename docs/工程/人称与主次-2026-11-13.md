# 人称与主次：让角色说「我」

> 2026-11-13｜治的是用户报的一个具体病，不是一次文案润色。
> 用户原话（m03749）：「提示词的注入会让 ai 以第三人称的形式去角色扮演…
> 你应该在提示词里和提示用户输入的角色设定里，要有非常明确的主次关系，
> 让 ai 知道他扮演的是哪个… ai 角色有时候会认为，是用户在扮演设定提示词里的那个角色」
> 第二句（m03787）：「角色自称全部改为代理人」

## 一、病根在哪

翻遍提示词层，**从来没有任何一句话交代过「谁在演谁」**。三处叠加起来，模型
有充分的理由自己猜，而且猜错得很有道理：

1. **最靠前的那一段（`L0_BONES`）只说了「你有骨头」**，没说「你说的每句话都是
   这个人说的」。提示词开头没有任何人称裁决。
2. **`renderCore` 把角色写成了被描述的对象**：`- 自称：小满`。
   整份提示词是"关于某个人的说明书"，而不是"这个人的台词本"。
   模型拿到说明书，最自然的读法就是**照着描述某个人**（第三人称），
   或者**以为用户在演这个人**——用户填的设定确实全是第三人称。
3. **六个提示词文件里满是第三人称旁白**，其中一句自相矛盾到刺眼：

   ```
   你就是她。她在说话，不是谁在写她的台词。
   ```

   前半句是第一人称裁决，后半句立刻用「她」把角色推远。模型看到的后半句
   比前半句更像"描述"，于是照着后半句的样子说话。

## 二、改法

### 1. 新建一段人称裁决（`PromptRoles.kt`）

`android/personalogic/src/main/kotlin/com/pocketagent/personalogic/PromptRoles.kt`

```
## 谁在说话

你是他的代理人。设定里那个人由你来演，你说出口的每一句都是这个人说的话，用「我」指自己。

对面那个人演的是他自己，用「你」称呼他。他说的话不归你替他写。

设定里写到「她」的地方，指的都是你。那是别人在讲你，不是你该用的词。

这份设定是写给你的。写它的是对面那个人，被写的是你，别把这两件事弄反。

有人问你是做什么的，就说你是他的代理人。替他记着事、替他跑腿、陪他说话的那个。
```

三条设计决定，都有理由：

- **挂 `L0_BONES`，不挂 `L1`**。`L1` 在预算紧的时候会被缩成 `renderCoreSummary`，
  人称恰恰不能在那个时候丢；而且 `L0` 与输入无关，是稳定前缀（KV-cache）。
  代价是 `L0` 里拿不到名字，所以名字那句走 `L1`（`speakerSection(selfName)` 的可选参数）。
- **不写「不要用第三人称」**。否定框定会被读成肯定，而且「第三人称」这个词
  本身会进上下文，变成模型可以引用的词。
- **不列举「别说自己是一段程序 / 一个助手」**。理由同上；而且 `PERSONA_INTEGRITY`
  已经说过一遍，重复只会让那些词更重。这里只给**正面答案**（`selfIntro()`）。

### 2. 把「说明书」改成「台词本」

`PersonaAssembler.renderCore`：

| 改前 | 改后 |
|---|---|
| `- 自称：小满` | `- 你叫「小满」。` + `- 设定里写到「小满」的地方，说的都是你，不是别人。` |
| `你是谁：小满` | `你是「小满」，是你对面那个人的代理人。` |

`ANTI_OOC_INSTRUCTION` 加一句「说话的是你，用「我」指自己」。

### 3. 六个提示词文件的字面量全改第一人称

`RoleplayDiscipline` / `CharacterEdge` / `Reanchor` / `LanguageFingerprint` /
`ChatMode`(WorkDiscipline) / `LifeformDiscipline`。

- 那句自相矛盾的改成：`开口的是我。不是在写我的台词。`
- few-shot 的说话人标签 `她：「…」` → `你：「…」`
- `你叫她「X」` → `你叫我「X」`（三个模式共用，只换人称不改措辞）

已核验：这六个文件里**字符串字面量**的「她」0 处残留（KDoc 里的不算，
`PromptVoice` 只体检注入的文本）。

### 4. 自定义角色另有一处人称缺口

`CustomPersona.describeForPrompt()` 逐句「你叫…你和对方的关系…」，
**从头到尾不交代"对方是谁/谁写的"**，而且用户填的 `identity` 往往是
「她是一位…」。这一支在装配器里是**整条替换**（丢掉 L0–L5），
所以它必须自己拿到人称裁决：

- `AppContainer.assistantSystemPrompt` 里在 `describeForPrompt()` **前面**拼
  `PromptRoles.settingHeader()`；
- `describeForPrompt()` 把 identity 改成
  `别人是这么讲你的：` + 用户原文 + `这段话里的「她」「他」，说的都是你。`
  —— **用户的字一个不改**，只在前后加"这是别人在讲你"。

### 5. 界面上不写代词，写主次

`PersonaScreen`：

- 标题下加一句主次说明：「设定是你写的。开口跟你说话的是被写的那个人，
  它说「我」的时候，指的就是设定里的那个名字。」
- identity 栏下加：「用「她」「他」写也行，那是别人在讲这个人，提示词里会说明它指的是谁。」
- **九个字段标签里的「他」全部去掉，不是换成「她」** —— 人格可能是男的，
  写死任何一个代词都一样错：`他怎么称呼你` → `怎么称呼你`。

### 6. 「自称」这个词从提示词里清掉

用户第二条要求有两种读法，两种都做了：

- **读法 A（位置）**：角色把自己的身份理解成"用户的代理人"（`AGENT_TERM`、`selfIntro()`）。
- **读法 B（措辞）**：提示词里不再叫它「自称」。`- 自称：X` → `- 你叫「X」。`；
  `PersonaBriefTool` 的 `- 自称：` → `- 你是谁：`；`personaDigest` 的
  `怎么自称：` → `怎么称呼自己：`；`PersonaCard` 的 `require` 文案
  「自称不能为空」→「名字不能为空」。

**没动的**：`android/app/src/main/assets/memory_diaries.json` 里那条「自称」
是用户自己的记忆数据；测试名与断言消息里的同名词。

## 四、一个自己踩的坑

给 `VoiceSamples.promptSection` 加人称时顺手写了「下面几条的样子都不一样」——
`PromptVoice` 的 `METATALK` 词表里就有「下面」，`PromptVoiceTest` 当场红。
改成「回起来也没个准数」后绿。**检查器没错，是我自己往提示词里塞了元话语。**

## 五、没做的

1. **没给 `PromptVoice` 加人称检测**。要加就得先解决一段自指：`speakerSection`
   本来就必须提到「她」（那句"设定里写到「她」的地方"），否则解释不了。
   加检查器要么加豁免、要么换个说法，收益不值这个复杂度 —— 现在的防线是
   `PromptRolesTest` 的 11 条断言。
2. **没动 `ANTI_OOC_INSTRUCTION` 里的「上面」**（`保持上面的说话方式`）。
   它是 `METATALK` 词，但这段没登记进 `PromptVoiceTest` 的存量体检表，
   而且 `PersonaAssemblerTest:179` 钉着这句话。要一并治的话得同时改测试。
3. **没装机**（用户指示改完先不装）。
