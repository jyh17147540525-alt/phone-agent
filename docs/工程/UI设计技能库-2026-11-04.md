### 2.3 `ui-reverse-engineer` 的取色脚本

```powershell
$P = "$env:DSH_HOME\skills\ui-reverse-engineer\scripts\extract_palette.py"

python $P shot.png                     # 主色 + 覆盖率 + WCAG 对比度 + 角色推断
python $P shot.png --colors 10         # 要更多颜色
python $P shot.png --regions 3x3       # 分九宫格取色（看区块配色差异）
python $P shot.png --crop 0,0,390,240  # 只取状态栏/头部
python $P shot.png --json              # 机器可读，喂给后续脚本
```

六步流程（SKILL.md 里）：采样本 → 拆结构 → 取色 → 量度量 → 交集法归纳 → 交付三件套（design-spec.md / tokens / 组件清单）→ 像素验收。
度量换算与阈值（dp=px×160/dpi、cap-height×1.42 反推字号、4/8 网格、48dp 触控、对比度阈值、模板感清单）在
`references\measurement-rules.md`。

## 三、和本项目的关系（重要，别用错）

本项目是 **Jetpack Compose + Material3**，`android/app/src/main/kotlin/com/pocketagent/ui/design/`
下已经有约 **2400 行**设计系统（`Tokens.kt` 276 / `Components.kt` 375 / `Interactive.kt` 378 /
`Glass.kt` 218 / `Inputs.kt` 210 / `Motion.kt` 208 / `MotionExtras.kt` 206 / `Navigation.kt` 148 …）。

因此：

1. **`ui-styling` / `design-system` 的代码不能搬**。它们是 shadcn/ui + Tailwind 的 Web 栈。
   可借的是**方法论**：三层 token 分工（primitive→semantic→component）、组件规格写法、状态穷举清单。
   要落到 Compose，映射关系是
   `primitive = Color(0xFF…) / 数值常量` → `semantic = LocalPalette.current.X`（本项目已经是这么做的）→
   `component = Components.kt 里的可组合项`。
2. **别重造 token。** 改视觉先改 `Tokens.kt` / 主题，不要在页面里写魔法数——`Tokens.kt` 开头注释里
   已经写明"所有视觉决策的单一事实来源""间距只用 4 的倍数""全站只有一个强调色"。
3. **配色上的一个事实，做差异化时要知情**：`frontend-design` 把「暖米色底（#F4F1EA 一带）+ 衬线标题 +
   陶土/赤陶强调色」列为**第一号 AI 模板特征**。项目当前正是"暖底 #F5F2EC + 衬线标题 + 陶土强调"。
   这不是错——是有意选的、且和"Claude 风格审美"的诉求一致；但既然 skill 明确点了这条，
   将来如果要"看起来不像 AI 生成的"，第一刀就该砍在这里（换强调色的色相，或把衬线限制到只有大标题）。
   这条留作判断依据，不是要求。
4. **动效已有底盘**（`Motion.kt` 208 行 + `MotionExtras.kt` 206 行 + `MotionPreference.kt`）：
   先读 `docs/工程/UI与动效优化方案-2026-11-02.md` 与 `docs/工程/高级动效设计提案-2026-11-02.md`，
   再决定用不用 skill 的建议，别覆盖已有结论。

## 四、怎么让它生效（已做完的部分 + 你要做的一步）

**已做**：DSH 默认没扫 `~/.dsh/skills`，所以往 profile 的 patch 层加了一个 provider 实例。
文件：`C:\Users\Mikel.Daniela\.dsh\profiles\desktop\cordis.patch.yml`（末尾追加）：

```yaml
- insert:
    - id: skill-filesystem-user-skills
      name: '@deepseek-ai/dsh-skill-filesystem'
      config:
        providerName: user-skills
        includeDefaultRoots: true
        watch: true
```

备份：同目录 `cordis.patch.yml.bak_before_skills_20261104-183809`。
`includeDefaultRoots: true` 会一并覆盖 `~/.dsh/skills`、项目 `.dsh/skills`、`~/.agents/skills`
（顺带把 `~/.agents/skills` 下的 gepeto、pinokio 也挂上了，无害）。

**你要做**：重启一次 DSH（patch 只在启动时应用）。
重启后在任意会话里 `skill ui-ux-pro-max` 能加载，就说明通了。

不重启也能干活：技能本体是 Markdown，`read` 上面表里的 `SKILL.md` 路径即可；
脚本都是独立 CLI，直接 `python` 跑。

## 五、DSH 加载 skill 的真实规则（排障用，都是从源码读出来的）

源码：`D:\dsh桌面版\resources\app\dsh\node_modules\@deepseek-ai\dsh-skill-filesystem\lib\index.js`

1. **只看 depth-1**：根目录下的 `<子目录>/SKILL.md`，或根目录里直接放的 `*.md`。子目录下的子目录不认。
2. **首行必须恰好是 `---`**。**UTF-8 BOM 会让整个技能被静默丢弃**（`\ufeff---` ≠ `---`），
   日志里只有一行 warn，很容易漏。本次就踩了这个坑（4 个文件被编辑器带上 BOM）。
3. front matter 必须是 YAML 映射，且 `name`、`description` 都是非空字符串。
4. `name` 必须匹配 `^[a-z0-9]+(?:-[a-z0-9]+)*$`（小写字母数字，单连字符分隔；不能有大写、下划线、空格）。
   `name` 不必等于目录名。
5. 拒收遗留键：`disableModelInvocation`、`modelInvocable`、`userInvocable`
   （改用 `disable-model-invocation`、`user-invocable`，值要能解析成布尔）。
6. 名字为 `.system` 的目录被跳过。
7. 有 chokidar watcher（depth 1）：新增/修改技能会触发刷新，改完不必重启（**前提是 provider 已经跑起来**）。

**自检脚本**（本项目新增，按上述规则逐条模拟）：

```powershell
python tools\verify\check_skills.py                       # 扫 $DSH_HOME\skills
python tools\verify\check_skills.py <dir>                 # 扫指定目录
python tools\verify\check_skills.py --json                # 机器可读
```

当前结果：`total=18 ok=18 bad=0`（10 个写作类 + 8 个 UI 类）。

另有一份离线真跑（用真实 provider 做 discover，不经过 DSH 主进程）可复现：
`%TEMP%\preview_skills.mjs` → `candidate count = 20`，其中 18 个 `source=user-dsh`、2 个 `source=user-agents`，
零 warning。
