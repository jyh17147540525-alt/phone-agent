# 角色扮演（RPCA / RPLA）论文选读：哪些结论能落到我们这个 app 上

> 这份文件接在 `docs/工程/提示词文风-学术依据-2026-11-06.md` 后面。
> 那份讲的是**文风**（人 vs 模型怎么写句子）；这份讲的是**角色扮演**这件事本身
> —— 模型扮一个人时会在哪里露馅、学术界怎么量它、哪些手段在没有训练权限的前提下可用。

## 0. 一句话结论

**角色扮演这个领域的主流论文是在"训模型"，我们是在"写提示词 + 拼上下文"，
所以能直接搬的结论不多；但它们的评测维度把"哪里会露馅"说得比我们清楚得多，
这部分照单全收。**

具体说：CharacterBench 那类工作告诉我们"角色特征在单条回复里是稀疏的"，
所以**单轮打分必然抖** —— 这正好解释了为什么我们那套"逐轮打分 + 滑窗看趋势"是对的，
而"这一句不像她"不该当结论。TBS 那篇告诉我们模型露馅最狠的一处是
**知识边界**（角色不该知道的东西它知道），这一条我们目前**没有**任何防线。

| 级 | 含义 |

## 2. 论文清单

### 2.1 角色扮演的评测维度（最有用的一类）

**CharacterEval: A Chinese Benchmark for Role-Playing Conversational Agent Evaluation**
（Tu et al., ACL 2024 Long, [arXiv:2401.01275](https://arxiv.org/abs/2401.01275)，中文基准）

- 说了什么：1,785 段多轮角色扮演对话 / 23,020 条样本 / 77 个中文小说与剧本角色；
  用 **13 个指标、4 个维度**打分；中文模型在中文角色扮演上比 GPT-4 更好。
- 对我们意味着什么：**"角色扮演好不好"是多维的，不是"像不像人"一个数**。
  我们已有的 `HumanScore` 只覆盖"像人"这一维（文风），
  角色一致性靠 `OutputGuard` + `MemoryGate`，**这两者互不知情**。
- 强度：**A**（有基准、有数据、有人工标注；但它是评测，不是方法）。

**CharacterBench: Benchmarking Character Customization of Large Language Models**
（Zhou et al., AAAI 2025, [arXiv:2412.11912](https://arxiv.org/abs/2412.11912)）

- 说了什么：22,859 条人工标注样本 / 3,956 个角色 / 25 类；**11 个维度分 6 个方面**，
  并且按"角色特征是否在每条回复里都显现"把它们分成**稀疏维度**与**稠密维度**；
  因为特征稀疏，"按回复打分"这种评法既不有效也不高效，所以他们为每个维度**定制提问**去诱发相关回复。
- 对我们意味着什么：**这是本文件里最有操作价值的一条。**
  ① 单条回复不像她 ≠ 漂移 —— 稀疏特征本来就不会每句出现，
  所以 `HumanScore` 必须在**窗口上聚合**（我们已经是这么做的：`StyleDrift` 滑窗 + 斜率）；
  ② 想知道某个维度还准不准，得**专门问一句能诱发它的话**，而不是等它自己冒出来 ——
  这条可以变成将来的"体检对话剧本"，现在没做。
- 强度：**A**（AAAI 2025，人工标注，公开数据集与 code）。

**CharacterGLM: Customizing Chinese Conversational AI Characters**
（Zhou et al., EMNLP 2024 Industry, [arXiv:2311.16832](https://arxiv.org/abs/2311.16832)）

- 说了什么：角色 = **属性**（身份、兴趣、观点、经历、成就、社会关系…）+ **行为**
  （语言特征、情绪表达、互动方式…）；人工评测看重 **一致性、像人、投入感** 三项。
- 对我们意味着什么：给了我们一张"人格卡该有什么"的检查表。
  拿它对照 `PersonaAssembler`：属性齐（骨骼/档案/关系/世界书），
  行为里**"互动方式"最弱** —— 她对不同话题的**反应模式**（被夸怎么回、被追问怎么躲）
  只有 `VoiceSamples` 六组样本在撑，没有显式建模。
- 强度：**A**（同行评议），但它是**微调**模型，不给我们提示词配方。

### 2.2 露馅发生在哪里

**Thinking Before Speaking: A Role-playing Model with Mindset**
（Zhang et al., [arXiv:2409.13752](https://arxiv.org/abs/2409.13752)）

- 说了什么：用人话说 —— **"能看出这是 AI 在演"的典型时刻，是它遇到角色不该知道的知识、
  或需要角色自己的经历/逻辑才能回答的问题时。** 他们的解法是给每段对话补上角色的
  **mindset（内心盘算）**，再掺入"超出角色知识"的样本做微调，让模型学会
  "按这个人的思路想"，而不是查自己的参数知识。
- 对我们意味着什么：**这是我们现在最缺的一条防线。**
  我们的提示词里全是"她是谁、她记得什么、她怎么说话"，
  **没有一句"她不知道什么"**。模型于是拿自己的世界知识去答，
  答得越对越不像她 —— 一个没上过网、不认字的人形女仆突然给你科普 HTTP 状态码，
  那一刻就露馅了。
- 强度：**B**（方法本身是微调，我们没法用；"知识边界是主要露馅点"这个**诊断**可外推，
  但他们的实验是在自建数据上做的）。

**Mitigating Hallucination in Fictional Character Role-Play**
（ACL 2024，[anthology](https://aclanthology.org/people/prarit-lamba/)）

- 说了什么：模型**参数里的世界知识会压过角色设定**，导致角色说出设定里不该有的东西；
  并给出缓解手段。
- 对我们意味着什么：与我们 `docs/工程/` 里"冲突注入"那一套同源 ——
  设定与常识打架时，**设定优先**必须有明文，否则模型默认相信自己的训练数据。
- 强度：**B**（同行评议；具体方法依赖训练与数据增强）。

**Nautilus Compass: Black-box Persona Drift Detection for Production LLM Agents**
（[arXiv:2605.09863](https://arxiv.org/abs/2605.09863)，预印本）

- 说了什么：生产环境里的 agent 会在长会话中漂 —— 忘记用户定过的约束、
  重犯已被指出的错、把之前的约定记串；主张**黑盒**检测（不看权重、只看行为）。
- 对我们意味着什么：**给我们的 `StyleDrift` + `HumanScore` 路线背书**：
  黑盒、只看输出的漂移测量是正当做法，不是我拍脑袋。
- 强度：**C**（预印本，且对象是 coding agent 不是角色扮演）。

### 2.3 综述（用来确认自己没漏大方向）

**From Persona to Personalization: A Survey on Role-Playing Language Agents**
（Chen et al., [arXiv:2404.18231](https://arxiv.org/abs/2404.18231)，被引 300+）

**The Oscars of AI Theater: A Survey on Role-Playing with Language Models**
（[arXiv:2407.11484](https://arxiv.org/abs/2407.11484)）

- 说了什么：把这一行分成"从早期 persona 模型 → 角色驱动 → 个性化"三段，
  给出三层分类法（数据、模型、评测）。
- 对我们意味着什么：确认我们的位置是**"零训练 + 上下文工程"**这一档，
  和主流论文（微调/RLHF）不是同一条赛道 —— 所以**别拿它们的分数当自己的目标**。
- 强度：**A**（综述，同行评议与否按各篇而定）。

## 3. 结论：他们说的 → 我们该怎么办

| 论文结论 | 我们现在 | 判断 |
|---|---|---|
| 角色特征在单条回复里是稀疏的（CharacterBench） | 已经用 40 条滑窗 + 斜率，不按单条下结论 | **一致**，且这是被论文支持的做法 |
| 评测要多维（CharacterEval 4 维 / CharacterBench 11 维） | `HumanScore` 只管文风；一致性在 `OutputGuard`，两者不互通 | **缺口 1** |
| 露馅主要在知识边界与"角色没有的经历"（TBS） | 提示词里只写"她是谁/记得什么"，**没有"她不知道什么"** | **缺口 2（最该补）** |
| 参数知识会压过角色设定（ACL 2024） | 有冲突注入与"设定优先"，但没有覆盖"她不知道"这一层 | **部分覆盖** |
| 行为 = 语言特征 + 情绪表达 + 互动方式（CharacterGLM） | 语言特征强（VoiceSamples/HumanText），情绪有激素，**互动方式弱** | **缺口 3** |
| 黑盒漂移检测是正当做法（Nautilus Compass，C 级） | 已是黑盒 | **一致** |

## 4. 为什么"照论文做"会走进死路

这些论文的收益大多来自**训练**：CharacterGLM 微调 6B–66B、TBS 微调、ACL 那篇做 RLHF。
我们是 BYOK 手机 app：**没有训练权限、没有固定模型、用户随时换模型**。
所以能搬的只有两类东西：

1. **诊断**（哪里会露馅）—— 可以搬，而且最有价值；
2. **评测维度**（该量什么）—— 可以搬，变成我们的检查器。

搬不了的（**别硬装**）：凡是"训练一个 reward model / 做 SFT / 改 logits"的，一律不搬。

## 5. 下一步（按性价比排序）

1. ✅ **"她不知道什么"那一节**（对应缺口 2）—— **2026-11-06 已落地**，见 §7。
   原计划是在人格卡里加知识边界字段；实际做法换了（不加字段，见 §7.1）。
   纯逻辑、可离线测。
   ⚠️ 前提是先想清楚默认值 —— 写错方向会把她变成一个什么都不懂的傻子。
2. **一致性打分并进 `HumanScore` 的窗口**（缺口 1）。
   现在 `OutputGuard` 只记账不参与趋势；把它的命中当作一维信号接进 `StyleDrift`，
   让"越聊越不像她"和"越聊越 AI"用同一条趋势线上报。
3. **"体检对话剧本"**（CharacterBench 的定制提问）。
   固定一组能诱发特定维度的话（被夸 / 被追问设定 / 被要求做她做不到的事），
   真机侧跑完看哪一维先掉。
   —— 这一步现在**有了新的抓手**：§7 落地的那三类反应模式，
   正好是"该问什么"的清单，问完看她的回应是否落在描述的形状里。

## 6. 这份文件自己的规矩

- 凡写"论文说了 X"，X 必须能在上面对应的链接里找到，**不许把综述里的转述当成实验结论**。
- 分级必须诚实：预印本一律 C；微调方法的效果**不能**外推成"我们加一句提示词也行"。
- 本文不是提示词，可以有标题与表格；但里面任何一句话**要进提示词之前**，
  先过 `PromptVoice.audit()`（见 `PromptVoiceTest` 的存量体检）。

## 7. 落地记录（2026-11-06）

### 7.1 实现：`CharacterEdge`（`android/personalogic/.../CharacterEdge.kt`）

三段，全部散文、无列表符/加粗/破折号（`PromptVoiceTest` 存量体检从九段扩到十一段）：

| 方法 | 对应论文 | 内容 |
|---|---|---|
| `knowledgeSection(known)` | TBS（缺口 2） | 她只知道上下文里写过的事；没写过就是不知道，可以说"不知道/没听说过/你说的那个我不懂"；记不清就说记不清，不许往下补；外面的事照实说没听过 |
| `reactionSection()` | CharacterGLM 的"互动方式"（缺口 3） | 被夸 / 被追问 / 被要求做她做不到的事 / 被指出说错了，四类情境各给**行为形状**（不列台词，台词在 `VoiceSamples`） |
| `mindsetSection()` | TBS 的 mindset | 先弄清对方要答案还是只想说话；说出口的只有最后那一句，判断留在心里 |

接线：`AppContainer.assistantSystemPrompt()` 里 `val edge = if (work) "" else CharacterEdge.promptSection()`，
拼装顺序 `discipline → edge → voiceSamples → workRules → permissionRules`
（规矩在前，示范在末屏）；装配日志新增 `角色边界 有(N字)`。

### 7.2 与 §5 原计划的两处偏离（都有理由）

1. **没有加人格卡字段。**
   原计划"在人格卡里加知识边界字段"，实际查证后放弃：
   鲸鱼娘不是代码里的实体（`PersonaPresets` 只有 MALE/FEMALE 两个通用预设），
   她的设定存在 app 数据库的用户自定义人格里。
   一旦在 personalogic 里硬编码任何一个角色的知识清单，
   就把这一层锁死在一个人格上，别的用户的人格拿不到。
   ⇒ 改成**不依赖数据输入**的规则：**上下文里没写的，就是不知道**。
   这条对任何人格都成立，也不需要用户先填一张表。
   `known` 参数保留并默认为空 —— 将来若真有人格卡字段，直接传进来即可。
2. **"心里过一遍"写成了"别说出来"。**
   TBS 的 mindset 在微调里是**内部**表示；我们在提示词里只能描述它。
   风险很清楚：写"她心里会盘算"会被模型当成"要不要把盘算讲出来"，
   而 `HumanScore` 的 SELF_NARRATION 判据（"我之所以这么说…"）正是这个病。
   ⇒ 措辞固定为"判断留在心里，不交代自己怎么想的"。

### 7.3 顺带修掉的一处漏网

`AppContainer` 的 `clueSection`（生理线索）原来还是 `clues.joinToString("\n") { "- $it" }`，
是第七批"提示词语体"漏掉的一处列表符。已改成一句一行（换行分隔、无 `- `），
保持"说得自然一点，不要逐条汇报"这句不变。
